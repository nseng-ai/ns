---
title: "objective"
description: "CLI reference for ns objective — list, inspect, validate, and archive Objective records."
---

`ns objective` is the deterministic command surface for [Objective](/docs/concepts/objectives)
records. It reads and maintains the records under `.ns/objectives/` in the current
repository — listing, showing, structural validation, archiving, and a small set of
agent-internal `exec` helpers.

The lifecycle mutations — creating an Objective, recommending next work, recording
progress, closing — are agent workflows driven by the Objective skills installed by
`ns init`, not public CLI subcommands. See the [quickstart](/docs/get-started/quickstart)
for that loop.

```bash
ns objective <command> [options]
```

`ns objective` is zero-config: it locates the repository and auto-detects the trunk
branch; no configuration file is required.

## Output formats

Every subcommand supports:

- `--format <format>` — `human` (default), `json`, or `markdown`/`md`. Use `json` for
  scripting and `markdown` when piping into an agent context.
- `--json-schema` — print the JSON Schema for the command's input and output, then exit.
  Agents and tools can discover the exact output contract without parsing docs.

## Commands

### `ns objective list`

List Objective records in the current repository.

```bash
ns objective list
ns objective list --names
ns objective list --status all
```

| Option | Description |
| --- | --- |
| `-n, --names` | Output slugs only, one per line. |
| `-s, --status <value>` | Filter by status: `active` (default), `open`, `closed`, or `all`. |

This is the command agents run before starting non-trivial work, to check whether the
task overlaps an in-flight Objective.

### `ns objective show`

Show one Objective record, including its associated branches and the annotations on its
edges to other Objectives.

```bash
ns objective show <slug>
```

### `ns objective check`

Validate an Objective record's structure: required files, required Markdown headings,
and the record frontmatter that carries edges and blocked state.

```bash
ns objective check <slug>
ns objective check --all
```

| Option | Description |
| --- | --- |
| `-a, --all` | Sweep every record's frontmatter across the active and archive roots instead of checking one slug. |

### `ns objective archive`

Move an Objective record out of active discovery (or back). Archiving is a location
move — the record keeps its slug and every file; nothing is deleted.

```bash
ns objective archive <slug>
ns objective archive <slug> --unarchive
```

| Option | Description |
| --- | --- |
| `-u, --unarchive` | Move an archived record back to the active set. |

Both open and closed Objectives can be archived. Closing is separate (and skill-driven);
archiving only controls whether the record appears in active discovery.

### `ns objective exec …`

`exec` contains deterministic helpers that Objective skills and agents use while doing
work, such as loading active orientation files, reading Objective records, running
tracking gates, and managing Objective Runner checkpoints. These commands are documented
through their own `--help` and `--json-schema` output because they are primarily an agent
contract rather than the human quickstart path.
