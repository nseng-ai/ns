---
title: "objective"
description: "Durable, checked-in Objectives for multi-session development work."
---

`objective` manages narrative roadmap records for work that should remain legible across sessions, branches, and PRs.

```bash
objective list
```

## Mental model

An Objective is checked-in Markdown, not hidden state. It gives a future human or agent the thesis, scope, roadmap, decisions, blockers, and completion evidence before they choose the next command.

## Install

`objective` is installed from an SDL checkout with a TypeScript source shim.

```bash
just install-objective
objective --help
objective --runtime
```

## Common commands

| Goal | Command | Boundary |
| --- | --- | --- |
| List Objective records | `objective list` | Read-only |
| Check one Objective | `objective check <slug>` | Read-only |
| Archive or unarchive an Objective | `objective archive <slug>` | Working tree |
| List candidates for agents | `objective exec list-candidates` | Read-only |
| Read Objective details | `objective exec read-objective <slug>` | Read-only |
| Summarize runner usage | `objective exec runner-subagent-usage` | Read-only |

## Agent interface

Objective skills use the CLI to keep multi-session work grounded in checked-in records. See the [objective skill](/docs/skills/objective) and [Objectives concept](/docs/concepts/objectives).
