SDL is a composable toolkit for plan-oriented agentic engineering. It helps humans and coding agents plan work, implement it in isolated environments, and carry context across sessions.

Each SDL tool is useful on its own. A team can start with worktree slots, Branch Memory, Objectives, PR feedback download helpers, or retrospective evidence without adopting every other part of the system first.

```bash
just install-slot
slot init --size 3
slot checkout feature-x
```

## Start here

1. [Quickstart](/docs/get-started/quickstart) — create a `slot` pool and check out your first branch-backed worktree.
2. [Installation](/docs/get-started/installation) — install the standalone tools from an SDL checkout.
3. [CLI conventions](/docs/concepts/cli-conventions) — learn output formats, exit codes, JSON envelopes, and hidden `exec` commands.

## What SDL provides

| Area | Use it for | First page |
| --- | --- | --- |
| Worktree slots | Parallel branches without stashing or re-checking out. | [`slot`](/docs/tools/slot) |
| Branch Memory | Branch-scoped context for plans, handoffs, and skills. | [`brmem`](/docs/tools/brmem) |
| Objectives | Checked-in narrative roadmap records for long-running work. | [Objectives](/docs/concepts/objectives) |
| PR feedback | Downloading structured PR review state for agents. | [`pr-address`](/docs/tools/pr-address) |
| Retrospectives | Deterministic evidence for branch/session recommendations. | [`aretro`](/docs/tools/aretro) |
| CI findings | Running and publishing configured PR-diff reviews. | [`roaster`](/docs/tools/roaster) |

## For agents

Agent workflows should prefer stable machine output when a tool provides it. The common pattern is a human-facing top-level command plus a hidden `exec` subgroup for skills and automation. See [CLI conventions](/docs/concepts/cli-conventions) before scripting against a command surface.
