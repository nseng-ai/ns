The `ns` CLI ships as a single npm package, `@nseng-ai/ns`. Installing it gives you the
`ns` binary — the shared command surface that both you and your coding agents use. The
first release bundle includes the Objective command surface (`ns objective`), repository
activation (`ns init`), and first-party harness artifact commands (`ns skills …`,
`ns update`).

> **Coming with the first release:** `@nseng-ai/ns` has a checkout-free bundle and local
> pack smoke path in the codebase, but it is not yet published to npm. The commands on
> this page describe the supported install path and will work as written once the first
> release is published.

## Prerequisites

- **Node.js 24.12 or later.** The published package is a self-contained bundle — it has
  no build step and no other runtime dependencies.
- **git.** ns is git-native: durable state lives in your repository as plain files and
  refs, not in a hidden database. You run `ns` inside a git repository.
- **A coding agent harness** for the full workflow: Claude Code, Codex, or Pi. The CLI
  works standalone, but Objectives are designed to be driven by agents.

## Install

Install globally:

```bash
npm install -g @nseng-ai/ns
```

Or run without installing:

```bash
npx @nseng-ai/ns --help
```

## Verify

From inside any git repository:

```bash
ns --help
ns objective list
ns init --help
ns skills list
```

`ns objective list` is zero-config: it auto-detects your trunk branch and reads
Objective records from `.ns/objectives/` in the repository. In a repository that has not
been set up yet it simply reports no Objectives — that's expected. The
[quickstart](/docs/get-started/quickstart) covers using `ns init` to bootstrap a
repository.
