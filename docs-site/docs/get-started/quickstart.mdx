title: "Quickstart"
description: "A numbered first run through SDL using slot as the first standalone tool."
---

Start with one tool. `slot` is the fastest way to feel the SDL pattern: a small CLI with predictable human output, optional machine output, and no hidden database.

## 1. Install slot

From an SDL checkout, install the TypeScript source shim:

```bash
just install-slot
```

Run `just ts-install` or `pnpm --dir ts install` first if the checkout is missing TypeScript workspace dependencies.

## 2. Create a pool of worktrees

```bash
slot init --size 3
```

`slot` creates ordinary Git worktrees under `$XDG_STATE_HOME/sdl/slots/repos/<repo>/worktrees/`, defaulting to `$HOME/.local/state/sdl/slots/...`.

## 3. Put a branch in a slot

```bash
slot checkout feature-x
```

The command prints a `cd` target. Change into that directory and work normally: edit files, run tests, and use Git or Graphite exactly as you would in any other checkout.

## 4. Inspect the pool

```bash
slot list
```

Every row is derived from `git worktree list`: assigned slots have a branch; available slots are detached at trunk and ready to reuse.

## 5. Learn the shared grammar

When you are ready to script SDL tools or hand work to an agent, read [CLI conventions](/docs/concepts/cli-conventions) for `--format json`, exit codes, and hidden `exec` subgroups.

## Next steps

- Install the rest of the tools from [Installation](/docs/get-started/installation).
- Learn why SDL is standalone-first in [The SDL umbrella](/docs/concepts/sdl-umbrella).
- Use [Parallel branches with slot](/docs/guides/parallel-branches) when several reviews or features need to stay open at the same time.
