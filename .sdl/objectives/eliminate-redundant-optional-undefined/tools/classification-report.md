# Optional-Undefined Candidate Classification (LM-assisted)

Generated by a 12-way fan-out of classification agents over the full AST candidate set
(`measure-objective.mjs --json` over every `ts/packages/**/src`), followed by an 8-way
re-adjudication pass over the dependency-injection / options-bag fields under the strict rule the
human chose (see "DI-bag rule" below). Each agent read the actual source at every candidate line
and traced producers. Machine-readable detail: `tools/classification.json` (one entry per
property, with `path`, `line`, `property`, `declaration`, `category`, `reason`, `confidence`, and
`producerNote`; re-adjudicated entries carry `readjudicated: true`).

Candidate set: **498** optional-undefined properties across **132** files / **31** packages
(722 files scanned).

- **Actionable now (`migrate_now`): 302** — internal shapes where present-`undefined` is pure
  redundancy: producers omit or pass concrete values; consumers use `??` / `=== undefined` /
  `=== true`. Change `?: T | undefined` → `?: T`.
- **Blocked on a producer (`migrate_after_normalization`): 125** — removable in principle, but a
  producer currently emits present-`undefined` (a direct `signal:`/`branch:`/`now:`/`stderr:`
  forward, or a Zod-optional CLI arg threaded through a gateway contract). Each carries a
  `producerNote` naming the exact forward to convert to the `...(x === undefined ? {} : { x })`
  spread-omit idiom.
- **Preserve: 71** — explicit present-`undefined` is semantically meaningful or mirrors a shape we
  don't own. **No false-positives, nothing deferred, and (after re-adjudication) no preserve
  resting on "DI bag precedent" — every preserve is now a concrete semantic reason.**

## DI-bag rule applied

The first pass left 88 DI/options-bag fields (`cwd`/`env`/`stdout`/`execApi`/`git` on `CliDeps`,
gateway-constructor options) inconsistently classified — some `preserve` on prior-Objective
precedent, some `migrate_now`. The human chose the **strict, evidence-based rule**: a DI field is
preserved only if a producer actually emits present-`undefined`, OR it is genuinely an env map /
signal / null-tolerant input / contract-mirroring fake. Re-adjudicating those 88 against producer
evidence moved **all 88** off `preserve`: **77 → migrate_now** (every producer omits or passes a
concrete value) and **11 → migrate_after_normalization** (a real direct forward, e.g.
`packagechk` → `clinkr` IO overrides, `cli-runtime` → `resolveIo`, `slot` `extension.ts` →
`stderr: ctx.stderr`).

## The two dominant `migrate_after_normalization` patterns

Nearly all 125 norm-blocked candidates reduce to two producer fixes:

1. **Direct optional forward instead of spread-omit.** `{ signal: options.signal }`,
   `{ now: input.now }`, `{ stderr: ctx.stderr }`, `{ stdout: deps.stdout }` emit a
   present-`undefined` key under `exactOptionalPropertyTypes`. Fix: `...(x === undefined ? {} : {
   x })`. Concentrated in graphite `branch.ts`, worktree-status `status.ts`, flow autobranch `now`
   cluster, plans `signal` forwards, kernel completion/context builders, clinkr IO via
   packagechk/cli-runtime.
2. **Zod-optional CLI args threaded through a gateway contract chain.** brmem is the exemplar:
   `operations/{list,get,check,copy}.ts` forward `request.key`/`at`/`branch` (from
   `z.string().optional()`) straight into the `BrmemReadGateway`/`BrmemGateway` interface, both
   real and in-memory implementations, plus the branch-context fake mirroring the same interface.
   Migrate as a **cluster** (interface + both gateways + fake together, after the operations
   normalize), not file-by-file. roaster `RunRoasterReviewRequest` is the same shape bound to
   `reviewRunRequestSchema`.

## Suggested sequencing

1. **Sweep `migrate_now` per package** (302) — mechanical `?: T | undefined` → `?: T`, validated by
   `just`. Densest: roaster (37), slot (35), brmem env fields, kernel (21), branch-context (20).
2. **Normalize the direct-forward producers**, then narrow their `migrate_after_normalization`
   targets — do the brmem gateway cluster and the graphite/worktree/flow `signal`/`now` forwards as
   coordinated edits.
3. **Encode the 71 preserve as the exclusion list** — they are already bucketed by concrete reason
   above, which is the natural exclusion-list schema.
