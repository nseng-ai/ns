# Standing Autonomous Runner Policy

## Summary

Reframed `eliminate-redundant-optional-undefined` from a bounded branch-local follow-up into a standing autonomy-designed Objective.

The Objective now has retirement-style completion criteria, a `## Definition of Progress`, and a `## Runner Policy` that lets future `objective-next` sessions pursue small local cleanup slices without human candidate selection when the slice is semantic, coherent, locally validated, and stays within repository-local edits and Objective tracking.

The roadmap now treats the delivered packagechk / GitHub PR feedback / pr-feedback-watch / preview-checks / worktree-status stack as the initial seed evidence, while the active standing rows define an operating loop: inventory candidates, classify them, choose the smallest safe slice, normalize construction paths before narrowing types, validate, record reusable findings, and repeat in later sessions.

## Objective Impact

Future runners should optimize for semantic progress rather than raw grep-count elimination. Keepable progress includes removing redundant present-key `undefined`, splitting loose external/input surfaces from stricter internal types, preserving compatibility/null-sensitive boundaries, and recording reusable classification findings.

The new policy explicitly stops autonomous execution before public compatibility risks, external schema ambiguity, broad validation fallout, oversized review slices, commits/PRs, merges, publishing, deployment, GitHub mutation, or other external write actions unless separately authorized.

## Follow-Ups

- Future `objective-next eliminate-redundant-optional-undefined` runs can select and execute small local cleanup slices under the Runner Policy after the normal execution preview/confirmation path.
- Record Semantic Updates only for kept progress, reusable classification findings, changed assumptions, validation evidence, or policy/roadmap changes; do not create iteration logs.
- If recurring accidental patterns suggest enforcement, recommend a separate bounded hard-guard / allowlist Objective instead of changing this standing Objective into a blanket ban.
