# CLI surface migration audit

This audit is the migration backlog for applying the signed-off clinkr house style beyond the already rebuilt representative surfaces.

## Migration policy

- **House style spec:** the normative side-effect result/progress grammar is consolidated in `house-style.md`. Cite it when porting a side-effect command instead of re-deriving the style from the ported renderers.
- **Eligibility gate:** migrate only command surfaces that have already been ported to the SDL extension architecture — either a project-local SDL extension entry or a first-party Capability command face. Standalone tools and unported capabilities are **extension-gated** until a later architecture milestone ports them.
- **Re-evaluation rule:** because extension migration is in progress, re-run the eligibility pass before each new batch and after material `sdl-extension-architecture` milestones.
- **Already migrated:** `sdl objective list`, `sdl flow cp`, and `sdl flow submit` are the reference implementations.
- **Migrate:** eligible human-facing command output that people read in a terminal.
- **Usually exempt:** hidden `exec`/skill primitives, JSON/Markdown payload readers, and full-screen TUI surfaces. Keep these machine-first unless they also expose a durable human-facing mode.
- **Ordering rule:** do eligible feature-building migrations first. Once the renderer feature set is stable, convert the remaining eligible table/status/detail commands mechanically.

## Mechanical rollout candidates after feature stabilization

Once the eligible P0 primitives above exist, migrate extension-ported surfaces in batches by shape rather than domain. Re-run the eligibility pass before starting any batch.

1. **List/table batch:** `sdl slot list/ls`, `sdl handoff list`, plus any newly extension-ported list surfaces.
2. **Status/check batch:** `sdl objective check`, `sdl flow changes`, plus any newly extension-ported status surfaces.
3. **Simple mutation summary batch:** `sdl slot claim/init/foreach`, plus any newly extension-ported simple mutation summaries.
4. **Detail/report batch:** currently no eligible non-exempt detail/report surfaces; populate only after an extension-ported surface appears.
5. **Destructive/preview batch:** eligible Slot/Handoff delete/gc/resize/free commands after the shared destructive-action renderer lands.

## Audit caveats

- This inventory is based on first-party TypeScript package `bin` entries, `sdl` dynamic extension help, hidden `exec` groups present on 2026-06-27, and an eligibility re-scope on 2026-06-28.
- Current eligible command-face families for this Objective are Flow, Objective, Slot, and Handoff. Standalone/unported families are marked extension-gated and must be re-evaluated as `sdl-extension-architecture` ports more commands.
- It deliberately excludes Pi slash commands and full-screen TUI internals; those are separate host/UI surfaces, not terminal CLI output.
