2 · Give each failure one home

Strong in-process

autobranch/latest-commit-transaction.ts · latest-commit-preparation.ts · latest-commit-formatting.ts · dirty-worktree.ts · dirty-transaction.ts

Before — one failure, three files

After — arm + verdict + message co-located

Same shape for both flows — the dirty and latest-commit transactions stop being organized on different principles.

Problem
Each autobranch failure is spread across its union arm, a classify case, and a format case; the twin transactions are split on different principles, so learning one doesn't teach the other.

Solution
Co-locate each failure's verdict and message with its arm in one catalog; give both flows the same prepare→transact→catalog shape.

  • locality: one failure, one edit site
  • twin flows share one shape
  • AutobranchFlowOutcome stops living in the wrong sibling
  • interface tests one catalog, not scattered cases

The fingerprint skip/force logic lives in one implementation; both the Flow Submit Boundary and regenerate call it.

Problem
Two modules run the same resolve→generate→edit sequence; only orchestratePrDescription respects the managed-region fingerprint, so the regenerate path can clobber an already-current body.

Solution
Fold both into one PR-description update module whose interface takes the fingerprint policy; delete the shared duplicate.

  • locality: fingerprint logic in one place
  • closes a latent overwrite bug
  • leverage: one interface, two callers
  • interface is the test surface for both paths

6 · Delete the forwarder shims

Worth exploring in-process

shared/git.ts (5) · text-helpers.ts (9) · checkpoint-message.ts (2) · submit/format.ts (3) · autobranch/short-sha.ts (3) · land-stack/graphite-metadata-command.ts (7)

Before — open a file, learn a renamed symbol

worktree.ts→ git.ts→ @sdl/capability-kit
model-generation→ text-helpers.ts→ capability-kit

Each shim adds a hop and a renamed symbol, no behavior. text-helpers.ts has one consumer; git.ts only prefixes Sdl→Flow.

Deletion test: deleting each shim moves nothing — it removes indirection at no cost. That is the signature of a shallow forwarder, not a module.

After — call the real interface directly

worktree.ts → @sdl/capability-kit
model-generation → capability-kit

Six files gone. Stable naming that earns its keep (e.g. shared/text-generation.ts, 8 consumers) stays.

Problem
Six single-purpose files exist only to rename or re-export one symbol; navigation bounces through them for zero added behavior.

Solution
Inline the rename/single-consumer shims into their callers; keep only re-exports that serve many consumers as a naming seam.

  • fewer hops per concept
  • shallow forwarders removed, no depth lost
  • type resolution stops routing through barrels
  • duplicate-named traps (two text-generation) reduced

7 · De-leak the submit gateway

After — classification behind the seam

Failure shape + its message live together, so a branch stops bouncing to submit-format.ts.

Problem
RealSubmitGateway mixes shelling out with Graphite-stderr classification, so the gateway interface leaks Graphite's error taxonomy; each failure branch splits across submit.ts and submit-format.ts.

Solution
Move stderr classification behind the gateway so it returns domain results; co-locate each failure shape with its message.

  • seam hides Graphite's dialect
  • locality: failure shape + message together
  • orchestration testable without stderr fixtures
  • 946-line file sheds two responsibilities
Top recommendation

Start with #1 — the Graphite command channel.

It is the deepest leverage in the package: one interface behind every land call site, with two adapters that genuinely justify the seam — the real gt runner in production, a scripted channel in tests. Today the land scenarios drive the outermost pi.exec, so the real sequencing bugs hide behind four wrapping layers; a single channel makes the pi triplet — a live, unguarded correctness hazard — disappear into one module. It unblocks #5 (presentation stops fighting the stream wrapper) and is independent of the in-flight Flow Land extraction, so it can land now.

If you'd rather bank a fast, low-risk win first: #3 closes a latent PR-description overwrite bug, and #6 deletes six forwarder files outright.
