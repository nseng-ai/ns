# Release refusal codes

Every refusal carries a `code` and a message. Look it up here before acting.
Codes marked **STOP** must be escalated to the user, not retried.

## Read this first: establish the stage before acting

Several codes are emitted from more than one phase, and the same code can mean
"nothing happened, retry" or "packages are live on npm" depending on where it
fired. Never act on a code alone. Establish the stage first:

```bash
rg -o '"stage": "[^"]+"' ts/dist/releases/<VERSION>/report.json
```

- **No report file** → preflight may have failed cleanly, or bump/qualification
  may have left partial local effects before the initial journal write. Inspect
  with `just release-reset <VERSION> --dry-run`; never assume cleanup scope.
- `preparing-candidates` → pre-checkpoint and potentially resettable through the
  typed reset workflow below.
- `candidates-prepared` → identity matters. A source-branch report with no
  deterministic release branch can be pre-checkpoint; a release-branch report is
  checkpointed. Let `release-reset` classify it rather than guessing.
- `checkpointing` → Graphite may already have created the checkpoint. Never
  reset automatically; preserve the report and inspect/resume.
- `publishing` / `published` → **packages may already be on npm.** Do not start a
  fresh release and do not change the version. Resume.
- `verified` → the release completed.

`release-command-failed` is the generic wrapper for *any* shelled-out command
that exited non-zero: preflight `git`/`gt` calls, the bump, qualification,
`npm view`, `npm publish`, and the registry verification all surface under it.
Use its `displayCommand` field plus the stage above to locate the real failure.
A `displayCommand` containing `release:verify-public` means the publish already
happened and only read-back verification failed.

## Supported pre-checkpoint reset

For a bump, qualification, or candidate-preparation failure, inspect first:

```bash
just release-reset <VERSION> --dry-run
```

Authorize only the exact plan it returns, either interactively with
`just release-reset <VERSION>` or non-interactively with `--yes`. The command can
restore partial or complete byte-exact public-manifest version bumps, an
optional lockfile diff, and the exact `ts/dist/releases/<VERSION>/` directory. A
recorded commit older than `HEAD` is allowed only on the same source branch when
Git proves it is an ancestor. The evidence surfaces that staleness and a complete
release-directory content fingerprint.

A reset refusal is not an invitation to clean by hand. Any release branch,
`checkpointing` or later state, pending/completed npm write, report/candidate
mismatch, unexpected tracked/untracked path, or semantic/representation manifest
edit beyond the version replacement preserves all state and requires
resume/manual recovery. Reset never calls npm or Graphite,
deletes branches, edits reports, or performs broad `ts/dist/` cleanup.

After a successful reset, restart with `just release-plan <VERSION>` and only
then `just release <VERSION>`.

## Preflight (no checkpoint — cheap to fix, but local effects may exist)

| Code                                                              | Means                                                                           | Do this                                                                                                                                                                                                                                                                                                                                                  |
| ----------------------------------------------------------------- | ------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `invalid-release-version`                                         | Not a concrete npm semver (a range, tag, or empty).                             | Pass a concrete version, e.g. `0.1.4`.                                                                                                                                                                                                                                                                                                                   |
| `release-worktree-dirty`                                          | Worktree has uncommitted changes. **Also emitted on resume** — check the stage. | Preflight: commit or stash, then rerun. On resume, see the Resume table before touching anything.                                                                                                                                                                                                                                                        |
| `release-on-trunk`                                                | Current branch is the resolved Graphite trunk.                                  | Create a branch (`gt create`) and rerun from it.                                                                                                                                                                                                                                                                                                         |
| `release-branch-untracked`                                        | Current branch is not tracked by Graphite.                                      | `gt track`, then rerun.                                                                                                                                                                                                                                                                                                                                  |
| `release-branch-collision`                                        | `transactional-npm-release/v<VERSION>` already exists.                          | A prior attempt checkpointed but its report is gone (a report would have resumed instead of reaching preflight). **STOP** — without the report you cannot resume. Check `npm view @nseng-ai/ns@<VERSION> version`: if it published, the version is spent — pick the next one. Only if nothing published is deleting the stale branch and rerunning safe. |
| `release-manifest-missing`, `release-manifest-inventory-mismatch` | Canonical source manifests do not match the intended public inventory.          | A code/inventory drift bug, not an ops problem. **STOP** and report — the package set in `public-packages/package-set.ts` disagrees with what is on disk.                                                                                                                                                                                                |
| `public-package-context-failed`                                   | The workspace package context could not be loaded.                              | A malformed manifest or unreadable workspace file. Fix it and rerun. Also emitted on resume.                                                                                                                                                                                                                                                             |

## Bump / qualify / freeze (nothing published yet)

| Code                                         | Means                                                                                          | Do this                                                                                                                                                                                                                                                                |
| -------------------------------------------- | ---------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `release-command-failed`                     | The bump or qualification command exited non-zero.                                             | A normal build/test failure. Read the surfaced output and fix the cause. If release-owned local effects remain and no checkpoint exists, use `just release-reset <VERSION> --dry-run`, authorize the exact reset, then restart with `just release-plan`.               |
| `release-change-set-mismatch`                | A required public manifest is missing from the tracked changes, or an unexpected path changed. | Read both halves of the message. `unexpected:` — something leaked into tracked paths; **STOP** and report, do not stage it. `Missing:` — a required public manifest did not change. An unchanged `ts/pnpm-lock.yaml` alone is valid and no longer causes this refusal. |
| `candidate-directory-create-failed`          | Could not create `ts/dist/releases/<VERSION>/`.                                                | Disk or permissions. Fix and rerun.                                                                                                                                                                                                                                    |
| `npm-pack-failed`, `npm-pack-invalid-output` | `npm pack` failed or returned unparsable JSON.                                                 | Usually a broken publish root. Fix the packaging problem, then rerun.                                                                                                                                                                                                  |
| `candidate-identity-mismatch`                | `npm pack` produced a different name/version than expected.                                    | **STOP** — the publish root does not match its manifest. A packaging bug.                                                                                                                                                                                              |
| `publish-root-inventory-mismatch`            | Qualified publish roots do not match the public inventory.                                     | **STOP** and report; qualification and the inventory disagree.                                                                                                                                                                                                         |

## Graphite checkpoint

| Code                                   | Means                                                    | Do this                                                                          |
| -------------------------------------- | -------------------------------------------------------- | -------------------------------------------------------------------------------- |
| `release-checkpoint-identity-mismatch` | Graphite did not create the requested branch/commit.     | **STOP**. Inspect Graphite state by hand; do not rerun blindly.                  |
| `release-checkpoint-dirty`             | Worktree unclean after the checkpoint.                   | **STOP** — something is writing during the release. Identify it before retrying. |
| `release-checkpoint-changed`           | Checkpoint identity changed while persisting the report. | **STOP**. Concurrent git activity; do not resume until you know what moved.      |

## Publication (registry writes may have happened)

| Code                                                                             | Means                                                                                                            | Do this                                                                                                                                                                                                                                                                                                                           |
| -------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `publish-confirmation-not-tty`                                                   | Publishing was attempted without a terminal.                                                                     | Rerun from a real interactive terminal. Do not try to automate the prompt.                                                                                                                                                                                                                                                        |
| `publish-confirmation-failed`                                                    | The prompt itself errored while reading input.                                                                   | Nothing was published. Rerun from a working terminal.                                                                                                                                                                                                                                                                             |
| `publish-declined`                                                               | The typed confirmation did not match.                                                                            | Nothing was published. Rerun and type `publish <VERSION>` exactly.                                                                                                                                                                                                                                                                |
| `published-package-hash-mismatch`                                                | npm already has this version with **different bytes** than the frozen candidate.                                 | **STOP**. This version is burned — it can never be released from this repo. Report to the user and pick a new version. Never unpublish or force.                                                                                                                                                                                  |
| `pending-write-ambiguous`                                                        | A write was in flight; the registry copy is not an exact match.                                                  | **STOP**. Cannot prove whether the write landed correctly. Escalate; a human must inspect the registry.                                                                                                                                                                                                                           |
| `pending-write-invalid`                                                          | The pending package is not in the frozen inventory.                                                              | **STOP** — the report is inconsistent. Escalate.                                                                                                                                                                                                                                                                                  |
| `invalid-publish-tarball`                                                        | The write plan contains a non-`.tgz` path.                                                                       | **STOP** and report; an internal invariant broke.                                                                                                                                                                                                                                                                                 |
| `npm-view-invalid-metadata`                                                      | The registry returned metadata that could not be parsed.                                                         | Surfaced through the registry-error path. Usually transient; resume. If it persists, **STOP** — the classification cannot be trusted.                                                                                                                                                                                             |
| `report-write-failed`                                                            | The journal could not be written. Mid-publish, this may mean a package published but the write was not recorded. | Fix the disk/permissions error, then resume. This is what the `pendingWrite` marker exists for: on resume an already-published exact package is adopted into `completedWrites` rather than republished. Do not hand-repair the report.                                                                                            |
| `release-command-failed` whose `displayCommand` contains `release:verify-public` | Published, but read-back verification never matched across the full retry ladder.                                | Packages **are** on npm. Do not start a fresh release and do not change the version. Resume with `just release <VERSION>`: residual propagation lag clears and already-published exact packages are skipped. If it still fails, read the verify output — a real hash difference is a `published-package-hash-mismatch` situation. |

## Resume

| Code                                                        | Means                                                                                                  | Do this                                                                                                                                                                                                                                                                                                    |
| ----------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `release-worktree-dirty`                                    | Resuming requires a clean worktree.                                                                    | Do not blindly stash — the tree may sit atop a partial publish. Identify what changed. If it is your own edit, revert it; the resume needs the checkout exactly as the checkpoint left it.                                                                                                                 |
| `wrong-requested-version`                                   | Passed a version that differs from the existing report.                                                | Rerun with the report's version, or finish/abandon that release first.                                                                                                                                                                                                                                     |
| `wrong-branch`, `wrong-commit`                              | Not on the release branch at the checkpoint commit.                                                    | `git checkout` the release branch at the commit recorded in the report, then rerun.                                                                                                                                                                                                                        |
| `wrong-parent-commit`                                       | Checkpoint recovery: the report's commit is not HEAD's **parent**.                                     | A `checkpointing`-stage report records the *pre-checkpoint* commit, so HEAD must be the checkpoint commit whose parent is `report.release.commit` — i.e. the tip of `transactional-npm-release/v<VERSION>`. Checking out the commit named in the report guarantees this refusal repeats.                   |
| `release-version-missing`, `release-versions-uncoordinated` | The working tree's public manifests are missing a version or no longer share one.                      | The checkout drifted off the report's version. Restore it to the checkpoint commit, same as `wrong-version`. Do not hand-edit manifests to match.                                                                                                                                                          |
| `wrong-version`                                             | Manifests no longer at the report's version.                                                           | Restore the checkout to the checkpoint commit. Do not hand-edit versions to match.                                                                                                                                                                                                                         |
| `candidate-missing`                                         | A frozen `.tgz` is gone (usually `ts/dist/` was cleaned).                                              | **STOP** if anything was published (`completedWrites` non-empty) — byte identity can no longer be proven. If nothing was published, discard the report **and delete the stale release branch** (the checkpoint already created it, so a fresh run would hit `release-branch-collision`), then start fresh. |
| `candidate-hash-mismatch`                                   | A frozen `.tgz` changed on disk.                                                                       | **STOP**. The candidates are no longer trustworthy. Escalate.                                                                                                                                                                                                                                              |
| `candidate-read-error`                                      | I/O failure reading a candidate tarball.                                                               | Transient or permissions. Fix the filesystem issue and rerun.                                                                                                                                                                                                                                              |
| `report-read-error`                                         | The report could not be read **or is corrupt** — this code also masks schema/JSON validation failures. | Do not assume "transient". Read the message: a genuine I/O error is fixable and resumable; a schema or JSON failure is a corrupt report — treat it as `report-invalid` below and **STOP**.                                                                                                                 |
| `report-read-failed`                                        | The initial report read failed outright.                                                               | Filesystem or permissions. Fix and rerun.                                                                                                                                                                                                                                                                  |
| `report-missing`                                            | Report vanished mid-resume.                                                                            | If nothing was published, start fresh (deleting the stale release branch). Otherwise **STOP**.                                                                                                                                                                                                             |
| `report-invalid`, `report-invalid-json`                     | The report is corrupt or fails schema validation.                                                      | **STOP**. Do not hand-repair it. Escalate with the report contents.                                                                                                                                                                                                                                        |
| `report-not-checkpointing`                                  | The report's stage changed between being read and being recovered.                                     | Not an operator choice — recovery is selected automatically and cannot be forced. This means the report was **mutated concurrently**. **STOP**; find what else is writing it.                                                                                                                              |
| `wrong-inventory`, `candidate-inventory-mismatch`           | The report's packages do not match the current inventory.                                              | **STOP** — the package set changed under a live release. Escalate.                                                                                                                                                                                                                                         |
| `recovered-report-write-failed`                             | Could not persist the recovered report.                                                                | Fix the write error (disk/permissions) and rerun.                                                                                                                                                                                                                                                          |
