## Flagged Ambiguities

Carry these collisions forward to focused package-context phases. Do not finalize them here.

- **Review / Comment**: distinguish Tripwires, Deep reviews, generic Reviews review definitions/runs, GitHub PR reviews, review threads, review comments, discussion comments, Reviews findings, Reviews findings comments, and inline finding posting.
- **State / status**: separate Clinkr `ExitStatus`, Git worktree/file status, GitHub PR state, Objective statuses, slot inventory status, package-check status, vibechk run status, and handoff branch state.
- **Active / root**: keep Active Objective Root, repository root, Git common dir, Base Namespace, and Graphite trunk distinct.
- **Branch / ref / start-point / snapshot-ref**: preserve Git Branch, Ref, Start point, brmem Snapshot Ref, Entry Locator, current branch, branch context, result branch, and Graphite stack node boundaries.
- **Graphite stack operations**: distinguish `@nseng-ai/capability-kit/graphite` as the support package for Graphite command adapters/facts, `ns slot gt` as the slot-owned command surface, Flow submit as a public workflow that composes neutral Graphite mechanics, and CCC/Flow-owned landing/autobranch orchestration.
- **Evidence / finding**: distinguish Objective completion evidence, retro deterministic evidence items, reviews findings, vibechk metrics/reports, and branch-retro recommendation judgment.
- **Plan / attachment / handoff**: distinguish enriched plan, saved plan, source branch plan file, branch context, attached plan, Branch Memory attachment, handoff artifact, continuation focus, and handoff technical locator.
- **Skill / agent / resource**: this sweep settled the two-channel management story (`ns skills` / `ns update` first-party provisioning plus `npx skills` third-party acquisition) and **Harness overlay** for areg-managed invocation policy files; later package-context phases still need to reconcile remaining areg inspector/resource language with Pi extension skill-expansion helpers.
- **Extension API**: the bare phrase "extension API" is banned anti-vocabulary — it conflates two distinct surfaces and must always be qualified. Write "ns extension API" (`@nseng-ai/kernel/sdk`) for the ns author SDK surface and "Pi runtime extension API" for the Pi surface (TUI, slash commands registered with `pi.registerCommand`, model-visible tools, `.pi/extensions`). Keep both distinct from a capability's **Capability API** (`@nseng-ai/<cap>/api`, imported in-process by a downstream **consumer** extension) and its kernel-loaded commands, defined in the root **Extension Layering** cluster.
- **Domain placement / layer**: capability domain logic lives only in the **Capabilities** (first-party extension packages built on the **Capability Kit**, `@nseng-ai/capability-kit`); the `@nseng-ai/pi` runtime host and `@nseng-ai/kernel` kernel are not domain homes. Capability Kit may host small shared first-party capability-building primitives (for example former transitional checkpoint/worktree/text helpers) when SDK/kernel are the wrong home, but it is not a product capability owner or public SDK by default. Domain formerly stranded in `@nseng-ai/pi/*` (for example, the objective-selection rules once at `@nseng-ai/pi/objectives`) has been relocated into its owning capability — `@nseng-ai/objectives` — and is re-consumed via that capability's **Capability API** (`@nseng-ai/objectives/api`). The SDK boundary is permeable downward over time but gated on proven generality, and opinionated above-SDK patterns such as gateways are expected to stay above the SDK (ADR 0012). Package Tier is now machine-declared (`ns.tier`) rather than inferred from report prose; the former `transitional` tier was deleted with `@nseng-ai/domain-primitives-transitional`. Keep Package Tier, domain placement, and Capability API cleanliness distinct when updating context.
- **SDK re-export ownership**: `@nseng-ai/kernel/sdk` re-exports and treats as its own vocabulary a minimal set of lower-package types and helpers, including `ExecResult` and `FormatCommandEvidenceOptions` from `@nseng-ai/foundation/exec`, `PositionalSpec` from `@nseng-ai/clinkr/raw`, schema builder `z`, and command-evidence helpers. The authoritative export list remains `ts/packages/kernel/docs/sdk-reference.md`; the context term records the ownership boundary, not a duplicate export inventory.- **Run / evaluation / metric**: reconcile vibechk run/bundle/status/metric vocabulary with retro session/evidence vocabulary and reviews review/finding output.
- **Changes / checkpoint / autobranch / submit / PR regeneration**: distinguish Flow-owned public lifecycle command ownership for workflows such as `changes`, `cp`, `autobranch`, `submit`, and `regenerate-pr`, CCC-owned repo source-control orchestration where the flow crosses primitives, neutral Graphite/Core mechanics, and Pi discovery/presentation adapters in `@nseng-ai/pi`.
