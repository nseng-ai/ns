## Flagged Ambiguities

Carry these collisions forward to focused package-context phases. Do not finalize them here.

- **Review / Comment**: distinguish Tripwires, Deep reviews, generic Reviews review definitions/runs, GitHub PR reviews, review threads, review comments, discussion comments, Reviews findings, Reviews findings comments, and inline finding posting.
- **State / status**: separate Clinkr `ExitStatus`, Git worktree/file status, GitHub PR state, Objective statuses, slot inventory status, package-check status, vibechk run status, and handoff branch state.
- **Active / root**: keep Active Objective Root, repository root, Git common dir, Base Namespace, and Graphite trunk distinct.
- **Branch / ref / start-point / snapshot-ref**: preserve Git Branch, Ref, Start point, brmem Snapshot Ref, Entry Locator, current branch, branch context, result branch, and Graphite stack node boundaries.
- **Graphite stack operations**: distinguish `@nseng-ai/extension-kit/graphite` as the support package for Graphite command adapters/facts, `ns slot gt` as the slot-owned command surface, Flow submit as a public workflow that composes neutral Graphite mechanics, and Flow-owned landing/autobranch orchestration.
- **Evidence / finding**: distinguish Objective completion evidence, Reviews findings, and vibechk metrics/reports.
- **Plan / attachment / handoff**: distinguish enriched plan, saved plan, source branch plan file, branch context, attached plan, Branch Memory attachment, handoff artifact, continuation focus, and handoff technical locator.
- **Skill / agent / resource**: `ns skills` / `ns update` owns npm-bundled first-party provisioning; `npx skills` owns repo-local and third-party acquisition, layout, lifecycle, and lock checks; **Skill Exposure Policy** and derived **Harness Overlay** ownership is limited to `ns skill-exposure` cross-harness exposure and the command-backed replacement invariant. Declarations always name explicit skill directories or direct `SKILL.md` paths.
- **Extension API**: the bare phrase "extension API" is banned anti-vocabulary — it conflates two distinct surfaces and must always be qualified. Write "ns extension API" (`@nseng-ai/sdk`) for the ns author SDK surface and "Pi runtime extension API" for the Pi surface (TUI, slash commands registered with `pi.registerCommand`, model-visible tools, `.pi/extensions`). Keep both distinct from an extension's **extension package API** (`@nseng-ai/<name>/api`, imported in-process by a downstream **consumer** extension) and its SDK-loaded commands, defined in the root **Extension Layering** cluster.
- **Domain placement / layer**: extension domain logic lives only in the first-party **ns extensions** (built on the **Extension Kit**, currently packaged as `@nseng-ai/extension-kit`); the `@nseng-ai/pi` runtime host and the `@nseng-ai/sdk` SDK are not domain homes. The Extension Kit may host small shared first-party extension-building primitives (for example former transitional checkpoint/worktree/text helpers) when the SDK is the wrong home, but it is not a domain owner or public SDK by default. Domain formerly stranded in `@nseng-ai/pi/*` (for example, the objective-selection rules once at `@nseng-ai/pi/objectives`) has been relocated into its owning extension — `@nseng-ai/objectives` — and is re-consumed via that extension's **extension package API** (`@nseng-ai/objectives/api`). The SDK boundary is permeable downward over time but gated on proven generality, and opinionated above-SDK patterns such as gateways are expected to stay above the SDK (ADR 0038). Package Tier is now machine-declared (`ns.tier`) rather than inferred from report prose; the former `transitional` tier was deleted with `@nseng-ai/domain-primitives-transitional`. Keep Package Tier, domain placement, and extension-package-API cleanliness distinct when updating context.
- **SDK re-export ownership**: `@nseng-ai/sdk` re-exports and treats as its own vocabulary a minimal set of lower-package types and helpers, including `ExecResult` and `FormatCommandEvidenceOptions` from `@nseng-ai/foundation/exec`, `PositionalSpec` from `@nseng-ai/clinkr/raw`, schema builder `z`, and command-evidence helpers. The authoritative export list remains `ts/packages/sdk/docs/sdk-reference.md`; the context term records the ownership boundary, not a duplicate export inventory.- **Run / evaluation / metric**: reconcile vibechk run/bundle/status/metric vocabulary with Reviews review/finding output.
- **Changes / checkpoint / autobranch / submit / PR regeneration**: distinguish Flow-owned public lifecycle command ownership for workflows such as `changes`, `cp`, `autobranch`, `submit`, and `regenerate-pr`, Herdr implementation workflows, their supporting launch mechanics, neutral Graphite/Core mechanics, and Pi discovery/presentation adapters in `@nseng-ai/pi`.
