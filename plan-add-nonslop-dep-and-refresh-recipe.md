# Install nonslop + refresh recipe

## Context

The `nonslop` Python CLI (`uvx nonslop create-project`) is not currently available inside this workspace. We already pull **skills** from `nseng-ai/nonslop` via `npx skills` and have an `update-nonslop-skills` recipe at `justfile:36-46`, but the `nonslop` CLI binary itself isn't installed — so `uv run nonslop ...` doesn't work.

The user wants to:

1. Install `nonslop` as a project dev dependency sourced from `https://github.com/nseng-ai/nonslop` master.
2. Have one `just` recipe that refreshes both the nonslop CLI install **and** the nonslop-sourced skills, replacing the current `update-nonslop-skills` recipe.

## Approach

### 1. Add nonslop as a git-sourced dev dependency

Edit `pyproject.toml`:

- Append `"nonslop"` to `[dependency-groups].dev` (keeping the list sorted alphabetically with the other non-workspace tools).
- Add a `nonslop` entry to `[tool.uv.sources]` pointing at the GitHub repo, master branch:

  ```toml
  [tool.uv.sources]
  twerk-core = { workspace = true }
  twerk-objectives = { workspace = true }
  twerk-pr-address = { workspace = true }
  twerk-slots = { workspace = true }
  nonslop = { git = "https://github.com/nseng-ai/nonslop.git", branch = "master" }
  ```

After this, running `uv sync` will clone nonslop from master at a pinned commit, install it into `.venv`, and `uv run nonslop --help` will work.

### 2. Replace `update-nonslop-skills` with `refresh-nonslop`

Hardcode the list of installed nonslop skills as a `just` variable at the top of the justfile, and replace the jq-based `update-nonslop-skills` recipe with a simple `refresh-nonslop` that does both steps.

Add near the top of `justfile` (after line 1):

```just
# Skills sourced from nseng-ai/nonslop. Keep in sync with skills-lock.json.
nonslop_skills := "ns-changelog-update ns-create-py-dev-cli ns-create-pypackage-project ns-dignified-python ns-fake-driven-test-layout ns-py-fake-driven-testing ns-pytest ns-refac-cli-push-down ns-refactor-swarm ns-resolve-merge-conflicts ns-setup-dprint ns-setup-python-ci ns-skill-management ns-skillx nsx"
```

Replace lines 36–46 with:

```just
refresh-nonslop:
    uv sync --upgrade-package nonslop
    npx skills add nseng-ai/nonslop --skill {{nonslop_skills}} --agent codex claude-code -y
```

Key choices:

- **Hardcoded skill list** — obvious, greppable, diff-visible when a skill is added/removed. The short comment on the variable flags the single source of truth (`skills-lock.json`) so future maintainers know where to cross-check.
- `uv sync --upgrade-package nonslop` forces the lockfile to re-resolve nonslop (pulling the latest master commit) and reinstalls the venv in one step. This is the idiomatic way to bump a single git-sourced dep.
- Two-line recipe — no bash shebang needed, no jq dep, no conditional branching. If the list is wrong, the failure is loud and obvious.

The 15 skills above match the current contents of `skills-lock.json` (every entry with `"source": "nseng-ai/nonslop"`).

### 3. Regenerate the lockfile

The plan execution will run `uv sync` once (via the first invocation of `just refresh-nonslop`) to write the initial `nonslop` entry into `uv.lock`. No manual lockfile editing.
