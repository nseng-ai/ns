# Self-Learning Loop for Implementation Lessons

## Summary

The Objective now instructs implementation agents to treat the standing Objective as a self-learning loop. Each implementation slice should update the Objective when the work reveals durable lessons future agents should inherit: a reusable heuristic, stale instruction, invalidated assumption, missing guardrail, proven pattern, or rule that has become too broad or too narrow.

Lessons are not limited to additions. They may be removals or edits to Scope, Non-Goals, Definition of Progress, Runner Policy, Implementation Guidance, Assumptions/Risks, Open Questions, roadmap guidance, or a new Semantic Update. Stale text should not be preserved merely because it helped an earlier slice.

## Objective Impact

The Runner Policy now explicitly requires future implementation passes to improve the Objective when implementation teaches durable context. Implementation Guidance adds a dedicated step for updating standing guidance with lessons learned. The roadmap's active standing row now includes the same learning-loop expectation and distinguishes durable Objective updates from ceremonial run logs.

This keeps the Objective open and standing, but makes future runs accumulate context over time instead of repeatedly rediscovering the same patterns or constraints.

## Follow-Ups

- Future implementation agents should review the Objective at the end of each slice and update it when a lesson would materially improve future work.
- Continue avoiding no-op or ceremonial updates; only durable lessons, changed assumptions, or meaningful guidance edits belong in Objective tracking.
