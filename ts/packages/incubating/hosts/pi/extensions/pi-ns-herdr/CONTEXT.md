# @nseng-ai/pi-ns-herdr

`@nseng-ai/pi-ns-herdr` is the Pi host adapter for Herdr. It owns Pi command registration, interaction, presentation, launch-option and command construction, session/model state, direct Pi discovery, and parity metadata for the twelve-entry `/ns:herdr:*` catalog: eleven base registrations plus optional `/ns:herdr:tab:handoff`.

Prompt, session, and Saved Plan implementation are symmetric across space and tab destinations. A tab prompt resolves the explicit caller identity through the Herdr Consumer Gateway caller-pane operation (backed by Herdr's caller-aware `pane current --current` query) immediately after command acknowledgement, before idle waiting, Git inspection, interaction, or mutation, selects the workspace ID, and creates a focused tab in that explicit caller space. Caller resolution fails closed; there is no environment or UI-focus fallback.

Session commands share one pending-generation coordinator and use a private, tool-less `pi --fork` process only to derive a checkout-portable implementation prompt from the persisted source session. Before the approval menu, they print the complete result as a TUI-only entry that remains absent from the source session's LLM context, disclose the source checkout and isolated-Slot destination semantics, and require explicit approval before entering the ordinary prompt implementation pipeline. Approval creates a collision-resolved branch, retains the prompt in Branch Memory, checks the branch out in a Slot, and launches a fresh, non-forked destination Pi with the Slot checkout worktree as cwd. The destination startup bootstrap verifies the branch and prepends destination-owned cwd/path-rebasing instructions before the retained prompt; the source reports the actual destination worktree after launch. These instructions reduce accidental edits to an old/source Slot but are not filesystem sandboxing or fail-closed path enforcement. Loading into the matching prompt command's editor for review/editing and cancellation remain mutation-free alternatives.

Herdr resource creation, labels, explicit caller targeting, Slot-backed prepared destinations, pane process launch, and the harness-independent semantic-label policy remain owned by `@nseng-ai/herdr` and are consumed through `@nseng-ai/herdr/api`. This Pi host passes resource descriptions and goals to Extension Kit's deep content-slug operation with that purpose-specific Herdr policy; Extension Kit owns model/config orchestration. Flat lowercase ASCII kebab labels use at most six words, strip useful trailing `space`, `workspace`, or `tab` when another word remains, and fail closed for every derivation failure. Goals never normalize the original goal as fallback. The host catches deep-operation throws, presents the existing error notification, and stops before resource creation or rename. Goal labels remain distinct from collision-resolved implementation branch labels. Exact caller-tab mutation selects the tab ID from the same typed caller-pane result before idle waiting, model work, or mutation; it fails closed with no environment or UI-focus fallback. User-facing language says **space**, **tab**, and **caller space**; **workspace** is reserved for upstream Herdr mechanics such as workspace IDs.

The dependency on `@nseng-ai/pi-ns-handoffs/handoff-launch` is an intentional host-to-host composition edge. The Handoffs adapter continues to own Handoff Artifact creation and slugging; this adapter adds Herdr preflight and destination launch behavior. `/ns:herdr:tab:handoff` resolves and captures the caller workspace in its own command handler before delegating to the Handoffs create flow, so a failed resolution stops the workflow before focus prompting, Git inspection, or Handoff skill loading.
