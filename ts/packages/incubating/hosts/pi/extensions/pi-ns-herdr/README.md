# @nseng-ai/pi-ns-herdr

Pi host adapter for Herdr's twelve-entry catalog: eleven base `/ns:herdr:*` commands plus optional `/ns:herdr:tab:handoff`. It delegates resource mechanics to `@nseng-ai/herdr/api` and owns Pi registration, interaction, presentation, launch-profile resolution, and canonical Pi argv construction for implementation workflows.

At every Pi session start, the adapter supplies Herdr's `$repo` custom token from the resolved Git-root basename. Local Herdr configuration chooses where that token appears. Pane reporting targets the exact caller. Workspace reporting uses only unanimous Git evidence from every pane in the first current tab and skips ambiguous or changing layouts. These presentation tokens are refreshed after startup events because Herdr does not restore them across server restarts; ns does not own the sidebar row styling.

Prompt, session, and Saved Plan implementation are symmetric across new-space and new-tab destinations. Tab prompt/plan commands target the explicit caller space. Session commands use a private, tool-less `pi --fork` process only to derive a checkout-portable implementation prompt. Before the approval menu appears, the complete prompt is displayed in a TUI-only transcript entry that remains absent from the source session's LLM context. Explicit approval is required before creating a collision-resolved branch and checking it out in an isolated Slot. The destination is a fresh, non-forked Pi session created with the Slot checkout worktree as its cwd. Herdr discloses the source checkout before approval and the actual destination worktree after launch; generator and startup instructions require inherited repository paths to be rebased under the destination cwd. This is an instruction-level accidental-edit guardrail, not a filesystem sandbox. Loading the generated prompt into the editor remains the explicit review/edit alternative to direct implementation.

The optional Handoff tab command composes the narrow `@nseng-ai/pi-ns-handoffs/handoff-launch` host interface and transports the caller's provider, model, and thinking level. Only exact absence of that subpath disables optional registration; other load failures propagate. The hidden Herdr command verifies the durable Handoff reference and constructs its canonical Pi launch at the narrow launch boundary.
