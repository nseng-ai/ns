# @nseng-ai/pi-ns-herdr

Pi host adapter for Herdr's twelve-entry catalog: eleven base `/ns:herdr:*` commands plus optional `/ns:herdr:tab:handoff`. It delegates resource mechanics to `@nseng-ai/herdr/api` and owns Pi registration, interaction, presentation, launch-profile resolution, and canonical Pi argv construction for implementation workflows.

Prompt, session, and Saved Plan implementation are symmetric across new-space and new-tab destinations. Tab prompt/plan commands target the explicit caller space. No-path Saved Plan commands use the curated `@nseng-ai/pi-ns-branch-context/session-plan-discovery` runner against the persisted Pi session, capture the exact effective discovery skill, and require semantic confirmation before trunk preparation, branch creation, Slot checkout, or Herdr mutation. They never fall back to the latest plan. Dry runs report discovery without selection, confirmation, saving, prompt injection, or mutation; non-UI and ephemeral sessions fail closed. Presented plans are persisted exactly through `enriched-plan exec save`, while plan-ready sessions receive a `/ns:plan:save` follow-up and stop. Session commands use a private, tool-less `pi --fork` process only to derive a checkout-portable implementation prompt. Before the approval menu appears, the complete prompt is displayed in a TUI-only transcript entry that remains absent from the source session's LLM context. Explicit approval is required before creating a collision-resolved branch and checking it out in an isolated Slot. The destination is a fresh, non-forked Pi session created with the Slot checkout worktree as its cwd. Herdr discloses the source checkout before approval and the actual destination worktree after launch; generator and startup instructions require inherited repository paths to be rebased under the destination cwd. This is an instruction-level accidental-edit guardrail, not a filesystem sandbox. Loading the generated prompt into the editor remains the explicit review/edit alternative to direct implementation.

The optional Handoff tab command composes the narrow `@nseng-ai/pi-ns-handoffs/handoff-launch` host interface and transports the caller's provider, model, and thinking level. Only exact absence of that subpath disables optional registration; other load failures propagate. The hidden Herdr command verifies the durable Handoff reference and constructs its canonical Pi launch at the narrow launch boundary.
