# Remaining Presentation Consolidation Assessments

## Summary

Assessed the three remaining post-extraction consolidation candidates — caps resolution, table rendering, and status-to-intent mapping — against the landed `@sdl/cli-theme` boundary. No production refactor is warranted for these rows; each candidate should remain outside the theme package unless future concrete surfaces prove a narrower shared primitive.

Evidence matrix:

| Candidate                                    | Evidence inspected                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 | Decision                                                                                                                                                                                                                                                                                                                                           |
| -------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Caps-resolution duplication                  | `@sdl/clinkr` owns the generic `Caps` model, process detection, settled non-interactive caps, host-extension parsing, IO override behavior, and `RenderCapabilities`; Flow's `resolveFlowStreamCaps` in `phase-stream.ts` adds command-host semantics by reading `SdlExtensionApi.extensions`, treating callback/stdout/stderr hosts as captured non-interactive sinks, and falling back to process caps only for direct CLI runs. Slot and Objective renderers already consume injected `RenderCapabilities` or default to settled caps at their own command faces.                                                                                                                                                                                                                               | Keep Flow's resolver Flow-local for now. Do not move caps resolution into `@sdl/cli-theme`; the theme package should remain a pure renderer over injected `Caps`. Do not promote another Clinkr or capability-kit helper until multiple command families need the exact same host-context adapter.                                                 |
| Table rendering / Markdown table composition | `@sdl/core/text-table` supports command-list tables with multiline continuation cells, optional rules, simple ANSI column/header styles, display-width measurement, and string output; it is used by Objective legacy/minimal list, Brmem list, Handoff list, Slot list, Areg skill-kind list, and Vibechk runs. `@sdl/cli-theme` `renderTable` supports styled/plain `Cell`s, caps-aware clipping/ellipsis, fill/auto/fixed widths, right alignment, and legend footers for house-style buffered surfaces. Objective pretty list deliberately composes lower-level theme primitives because it has branch-attribution tree subrows and an outstanding-change gutter. Markdown output remains hand-authored only where command-specific escaping, report sections, or simple pipe rows are needed. | Keep `renderTextTable` and `renderTable` intentionally distinct. Do not add a Markdown table composer yet; repeated domain-free Markdown boilerplate was not found. A future lower terminal-text primitive should be assessed only when a concrete surface needs multiline continuation plus caps-aware clipping plus styled/plain cells together. |
| Status-to-intent mapping helpers             | `@sdl/cli-theme` already owns closed presentation mappings: `ResultBlockKind` to success/error/warn headline styling and `PhaseState` to status-line glyph/color grammar. Domain packages keep their own mappings where status encodes policy: Flow git/Graphite failure/refusal classification and transcript mining; CCC land and autoslot distinguish visual result kind from notify level/exit routing; Objective list maps open/closed records to local status cells; Slot navigation maps clipboard success/failure guidance locally.                                                                                                                                                                                                                                                        | Keep domain status policy local. Do not add status-to-intent promotion helpers to `@sdl/cli-theme` now; promote only future domain-free presentation cell helpers after multiple unrelated normal human surfaces share the same status vocabulary without routing, exit, or domain semantics.                                                      |

## Objective Impact

- Completed the remaining caps-resolution, table-rendering, and status-to-intent roadmap assessment rows.
- Resolved the remaining non-Slot consolidation questions without production code changes.
- Reinforced the final package boundary: `@sdl/cli-theme` owns SDL house-style presentation primitives and closed visual grammars; Clinkr owns caps/IO/stream mechanics; command/capability packages own host adapters, domain status policy, routing, exit behavior, and command-specific Markdown/report composition.
- The Objective now appears ready for final reconciliation and likely closure if the parked stream/redesign/hidden-surface items remain intentionally parked.

## Follow-Ups

- Run ordinary validation/format checks for the Markdown tracking edits, then consider `objective-close` for `sdl-cli-theme-extraction` if the current completion criteria are satisfied.
- Revisit caps host adapters only if another command family needs Flow's exact `SdlExtensionApi` resolution semantics.
- Revisit table consolidation only when a concrete normal CLI surface needs both `renderTextTable` multiline continuation behavior and `@sdl/cli-theme` caps-aware styled-cell clipping.
- Revisit status-to-intent helpers only for repeated, domain-free human presentation vocabulary; keep routing/exit/status policy out of the theme package.
