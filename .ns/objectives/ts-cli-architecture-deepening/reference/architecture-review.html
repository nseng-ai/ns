Problem

Three modules encode one semantic — "given a PR, produce its description." The decision of when to generate lives in apply; the fingerprint it reads lives in pr-description. The interface is nearly as wide as the implementation.

Solution

One module, one entry point returning a discriminated result; viewing, fingerprinting, generation, and prewritten reconciliation become private implementation.

Deletion test

Delete apply and the fingerprint/overwrite logic reappears, split across the loop and pr-description. Complexity concentrates when merged — earns its keep.

Wins

  • locality: PR-description logic in one place
  • tests assert state→result, not 3-file scenarios
  • interface shrinks; implementation absorbs the wrappers
  • the *when-to-generate* decision finally gets tested

Problem

Assembling a SlotInventory — worktrees, occupancies, branch tips, in-progress operations — and the reading of it are tangled; three callers pattern-match SlotRecord.branch === null to re-infer state.

Solution

A reconciler module owns merging worktree state with occupancy metadata and exposes reconcile() + a pure occupancy lookup. SlotRecord becomes immutable output.

Deletion test

  • callers stop hand-built inventory fixtures
  • locality: occupancy rules in one module
  • navigation stops re-listing worktrees

Callers get a branch or an error — Graphite's algebra stays inside.

Problem

SlotGtGateway exposes raw topology discriminants (type: "parent" | "failure" | "untracked_branch"); navigation entangles git checkout side effects with Graphite reasoning. Tests set up both gt and git mocks for a single move.

Solution

A GraphiteStackNavigator adapter absorbs the discriminants and error classification; its interface is { branch | error }.

Respects the Graphite-boundary rule

slot gt is the canonical opt-in Graphite surface — its name is the contract. The adapter stays inside that group and must use Graphite plumbing (gt parent/children --no-interactive), never parsed gt ls display output.

Wins

  • tests mock one narrow contract, not Graphite's algebra
  • git vs Graphite reasoning separated
  • Graphite version drift contained in the adapter
  • interface shrinks; implementation absorbs the variants

Refs + validation computed once, behind a parse() seam.

Problem

The BrmemGateway only returns results — ref naming (buildSnapshotRef, encodeBranchName) and validation live in side modules that operations and downstream packages import directly. The storage model is public.

Solution

A BrmemEntryLocator (with a validating parse()) absorbs ref layout + validation; a thin BrmemEntriesGateway works in locators. Callers pass (namespace, key, branch) — never construct refs.

Deletion test

Delete ref-layout and ref construction reappears inline across operations, handoff, and branch-context. Highest reuse surface in the survey — clearly earns its keep.

Wins

  • leverage: one seam, brmem + handoff + branch-context
  • encoding rules change in one place
  • locality: ref/validation bugs concentrate
  • operations test against a fake entries gateway

Problem

Roaster's 144-line Pierre adapter is pure and reusable-looking — but nothing else parses diffs today. Moving it now buys a seam for an imaginary caller.

Solution

Leave it in roaster. Trigger: when pr-address (or another CLI) needs hunk geometry, lift parseUnifiedDiff + commentableRightSideLines to @asdl/core then — two real adapters.

⚠ Contradicts the spirit of ADR-0007 — surfaced only as a watch-point

ADR-0007 deliberately kept roaster a thin Pierre adapter and rejected broadening its parser surface. Relocating the adapter is compatible only when a real second consumer exists; doing it speculatively re-opens a decision the ADR already settled. Listed so a future review doesn't mistake the one-adapter seam for a missing one.

Wins (only once two consumers exist)

  • leverage: one parser, two GitHub-facing CLIs
  • parse edge cases tested once in core

Top recommendation

Highest leverage, clearest deletion test, and it makes the storage model stop leaking — the single biggest AI-navigability win here.
