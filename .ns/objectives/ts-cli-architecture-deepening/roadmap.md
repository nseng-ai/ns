# Roadmap

## Work

- [x] **Collapse the PR-description pipeline into one deep module** (`asdl-core/submit`) — shipped in `pr-description-orchestration.ts`: one single-PR operation now owns viewed PR details, prewritten reconciliation, fingerprint matching, generation, and edit results, while `submit-pr-descriptions.ts` is a thin aggregate and `regenerate-pr` uses the same orchestration path. Validation evidence: `pnpm --dir ts run test -- packages/sdl-core/test/pr-description.test.ts packages/sdl-core/test/pr-description-orchestration.test.ts packages/sdl/test/scenario/submit-cli.test.ts packages/sdl/test/scenario/regenerate-pr-cli.test.ts`, `pnpm --dir ts run check`, `pnpm --dir ts run fmt:check`, and `pnpm --dir ts run lint` pass locally.
- [x] **Make `TextGenerationGateway` a real seam** (`asdl-core/submit`) — shipped via `ScriptedTextGenerationGateway` exported from `@sdl/core/testing`, with request recording and `assertDone()` behavior mirroring the existing scripted command helpers. Orchestration tests use it to assert state→result behavior without real model calls.
- [x] **Collapse slot-dispatch into one orchestration module** (`ccc/cmux`) — **moved to `ts-cli-core-structural-cleanup`** (not shipped here). Target: a `SlotDispatchPlan` owning the branch → Branch Memory payload → slot checkout → cmux-workspace sequence; `dispatch-prompt`, `dispatch-from-trunk`, and `dispatch-plan` handlers become thin call sites. *Strong. First confirm whether `slot-dispatch-plan.ts` is already most of the target shape (Open Question, carried into the survivor row).*
- [x] **Hide occupancy reconciliation behind the slot inventory** (`slot`) — **moved to `ts-cli-core-structural-cleanup`** (not shipped here). Target: a reconciler module owns merging worktree state with occupancy metadata and exposes `reconcile()` plus a pure occupancy lookup; `inventory`, `planning`, and `gt/navigation` stop pattern-matching `SlotRecord.branch === null`. *Strong.*
- [x] **Put a stack-navigator adapter over Graphite's discriminants** (`slot/gt`) — **moved to `ts-cli-core-structural-cleanup`** (not shipped here). Target: `GraphiteStackNavigator` absorbs topology discriminants and error classification behind `{ branch | error }`; git vs Graphite reasoning separated. *Strong. Must stay inside the `slot gt` boundary and use Graphite plumbing (`gt parent/children --no-interactive`), never parsed display output.*
- [x] **Deepen Branch Memory behind an entry locator** (`brmem` / `handoff` / `branch-context`) — **moved to `ts-cli-core-structural-cleanup`** (not shipped here), reframed there as the next-layer deepening on that Objective's already-shipped gateway migration. Target: `BrmemEntryLocator.parse()` and a thin `BrmemEntriesGateway` absorb ref naming + validation that currently leak into brmem operations, handoff, and branch-context. *Strong. Highest leverage in the survey; widest blast radius — treat ref encoding as compatible and cover it with the locator's own tests before migrating callers (see Risk).*
- [x] **Replace the shallow brmem adapter with a plan-attachment module** (`branch-context`) — **moved to `ts-cli-core-structural-cleanup`** (not shipped here), reframed there as a branch-context capability/domain seam and likely input to the future branch-context capability-extension migration under `sdl-extension-architecture`. Target: `PlanAttachmentStorage` hides namespace + entry-key semantics so `attach` and `attached-plan` work in slugs. *Composes onto the brmem entry locator.*
- [x] **Pull objective-markdown rules into one validator** (`objective`) — **moved to `ts-cli-core-structural-cleanup`** (not shipped here). Target: `ObjectiveMarkdownValidator` owns objective/roadmap/update structure so schema changes land in one module; operations stop re-deriving headings. *Worth exploring; if a live `objective` capability migration takes ownership first, cross-reference instead of duplicating.*

## Parked

- [ ] **Decide disposition of lifting diff parsing into `asdl-core`** (`roaster` / `pr-address` / `asdl-core`) — **parked in place here, not migrated.** Hold as a one-adapter watch-point; relocate `parseUnifiedDiff` / `commentableRightSideLines` only if a real second consumer (e.g. pr-address) needs hunk geometry. *Speculative and bound to this Objective's Completion Criteria lifecycle: stay a watch-point, or be `rejected-with-ADR` as an ADR-0007 amendment. Contradicts the spirit of ADR-0007, which deliberately kept roaster a thin Pierre adapter; deliberately not moved into the "no behavior changes / verified findings" survivor, which has no home for a speculative ADR-tension watch-point.*
