# Manual Loop Crystallized as a Production Steelthread

## Summary

A steering decision ended the deliberate ideation phase and rejected a throwaway
prototype as the gate to implementation. The resolved requirements are coherent enough
to build the manual-first loop properly; constructing disposable glue would duplicate
the production seams and then discard the most useful exercise evidence.

The Objective is now a Steelthread Objective for the thinnest production-quality local
journey:

1. explicit revision-range and applicable-roster confirmation;
2. one consistent range feeding multiple foreground review runs, with failures and
   coverage gaps retained rather than aborting the roster;
3. one minimal structured run record with verbatim source-attributed findings;
4. proposed-and-correctable clustering, conflict flags, and actionability;
5. engineer-confirmed bulk dispositions with full per-finding accounting; and
6. an ordered, traceable planned-PR list for manual remediation.

Representative real use moves to the end of the steelthread as production completion
evidence. It is no longer a pre-crystallization prototype question. Autofix, disposable
candidate branches, validation, adoption, and submit/ship remain parked breadth after
the manual thread lands.

## Objective Impact

- The Objective's ideation framing and Frontier were replaced with steelthread framing,
  production completion criteria, and dependency-ordered execution slices.
- The prototype Question Row was dropped rather than resolved: the user ruled the
  throwaway approach out in favor of building the bounded journey properly.
- The crystallization Question Row was resolved by this decision. The implementation
  path is now Reviews roster/range execution → aggregation and manual resolution →
  complete local interaction → representative production exercise.
- The minimal-artifact and proposed-and-correctable decisions remain binding. The
  steelthread must not revive speculative IDs, staleness machinery, canonical
  cross-source architecture, or future-consumer requirements without real evidence.
- The Objective remains open; no implementation slice has yet completed.

## Follow-Ups

- Begin with the Reviews production core and preserve its read-only producer boundary
  and existing single-review command compatibility.
- Let representative production use correct the contract before closure, especially
  content-tuple reference awkwardness, run-level provenance, and resume behavior.
- Resume autofix safety and validation questions only after the manual steelthread
  lands; do not pull Flow submit/ship or broader agentic CI/CD into this Objective.
