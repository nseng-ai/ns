# Proposed First-Party Skill Destination Map

## Status and review boundary

This document proposes the complete initial destination map for the 58 first-party
canonical skills. It is a review artifact for the joint ADR 0046/map approval gate. It is
**not approval**, does not authorize a move, and makes no publication or support
commitment. `pr-make-accountable` is the first proposed `public` skill; that verdict is an
explicit support commitment rather than an inference from usefulness or portability.

Inventory revalidation date: 2026-07-26. A fresh one-level inventory found exactly 58 real
`skills/<identity>/` directories containing `SKILL.md`; its sorted identities exactly match
`skill-tree-design-inventory.md`. Every `SKILL.md` frontmatter `name` also equals its
current directory identity. **Inventory drift: none.**

## Family vocabulary

Families name durable owners, not visibility, invocation namespaces, packages, or generic
implementation disciplines. The same family may occur in more than one disposition.

- `agent-engineering`: agent-facing workflow and CLI design, context analysis, and scalable
  transformation practice.
- `branch-context`: saved plans and branch-attached implementation context.
- `flow`: the ns Flow command wrappers.
- `handoff`: directed continuation handoffs.
- `code`: internal source-control, stack, validation, and repository workflows whose stable
  skill identities use the `code-` prefix.
- `prs`: public and incubating PR feedback and authoring workflows.
- `objectives`: the Objective model and its lifecycle/runner workflows.
- `pi-host`: Pi-specific structured-UI backend skills.
- `planning`: README-first design and conversion of findings into landing plans.
- `repository-operations`: repository setup, changelog, release, and uncommon maintenance
  operations.
- `review-system`: review definitions, Tripwires, topology analysis, orchestration, and
  review-to-remediation workflows.
- `skill-system`: first-party skill acquisition, exposure-aware management, and auditing.
- `typescript`: portable TypeScript doctrine and the ns-specific overlay/review adapter.

Two durable product skills are approved exceptions to family nesting:
`skills/incubating/brmem/` and `skills/incubating/slots/`. Their product identities are
already the stable owner boundary, so a repeated one-skill family folder would add no
information.

## Runtime lookup recommendation

Runtime expansion should resolve first-party skills by globally flat identity through the
existing `.agents/skills/<identity>` overlay, not by recursively searching the nested
canonical tree and not by introducing a generated identity-to-source catalog solely for
runtime. The flat overlay is already the harness contract, preserves vendored and
first-party lookup uniformity, and avoids ambiguous duplicate leaves. Runtime descriptors
that currently probe `<repo>/skills/<identity>` should drop that direct-canonical
candidate (or replace it with the explicit `.agents/skills` root); diagnostics should name
the flat candidate actually checked. Existing containment and realpath checks must still
reject an overlay symlink escaping the permitted repository/harness root.

Canonical destination paths remain explicit data for **management-time** consumers:
`skills-lock.json`, Skill Exposure sidecars, first-party provisioning catalogs, package
publish extras, mirror-target synthesis, and migration checks. Those consumers must use
this map (materialized in their existing explicit configuration where needed), not infer
canonical paths via runtime recursive discovery. `.pi/settings.json` exclusions,
replacement registries, backing-skill command keys, package `publishPath`s, and harness
invocation names remain flat identities.

## Atomic migration checklist and closure review

The approved cutover must classify references rather than bulk-replace text:

1. Move all 58 canonical directories together and retarget all first-party
   `.agents/skills/<identity>` symlinks; leave `.claude` flat through `.agents` and leave
   vendored real directories untouched.
2. Update all 58 lockfile `source` paths, explicit Skill Exposure inputs/sidecars, and the
   `justfile` one-level enumerator. Reapply policy without changing the 14/34/10 exposure
   distribution unless separately approved.
3. Make acquisition/management and validation understand exactly
   `skills/<disposition>/<family>/<identity>`; do not retain flat canonical fallback.
4. Update explicit provisioning catalog entries, Objective package publish-extra
   `sourcePath`s, mirror-target synthesis, tests, fixtures, and mutable docs while retaining
   flat destinations/publish identities where intended.
5. Implement the flat-overlay runtime recommendation above and verify native invocation,
   command-backed expansion/diagnostics, internal handling, containment, and replacement
   registry behavior.
6. Update live `AGENTS.md`, prompts, workflows, extension references, review fixtures, and
   skill-internal root-relative sibling references. Preserve accepted ADRs, immutable
   Semantic Updates, closed records, and genuinely historical evidence unless a live link
   is broken.
7. Reconcile the four Flow skills' current `metadata.internal: true` with their approved
   incubating disposition. Do not otherwise redesign metadata, content, triggers, or
   exposure in this structural slice.
8. Review closure manually: the public `pr-make-accountable` workflow must not require
   inward dependencies, every incubating required dependency must be public/incubating,
   and internal dependencies may point anywhere. In particular, verify Objective,
   Branch Context, handoff, Flow, PR Feedback, Graphite, and Slots do not silently require
   an internal skill or private-only command.
