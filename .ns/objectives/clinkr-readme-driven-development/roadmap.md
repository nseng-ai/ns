- [x] Settle the original cold-audience Clinkr story and approve the filesystem-first direction, app-owned execution/completion, explicit outcomes, command-level rendering, narrow raw escape hatch, invocation-owned context, and runtime discovery without manifests or production codegen.
- [x] Build a broad steelthread through Clinkr, Foundation, SDK composition, Flow, Objectives, and Brmem. It proved the filesystem-oriented result and exposed contract refinements around command metadata separation, CLI-directory ownership, framework usage-error schema composition, presentation-ready string rendering, status-specific outcome schemas, packaging, and real-host behavior.
- [x] Rebaseline the Objective from prototype reconciliation to a clean rebuild. Bless the steelthread as evidence rather than production architecture; record contract changes in `references/steelthread-contract-changes.md`, implementation lessons in `references/steelthread-implementation-lessons.md`, and the decision in `updates/2026-07-27-steelthread-rebuild-rebaseline.md`.
- [~] Review and bless `references/README-draft.md` as the cold-audience product contract, with `references/implementation-contract-notes.md` preserving detailed acceptance behavior intentionally removed from that narrative. The public builder, context mode, extension-source collision, raw-command constructor, and export-boundary questions are settled; remove remaining provisional wording, settle the explicit runtime/type representation for contextful command definitions, and add compile fixtures for every TypeScript example plus an executable fixture for the primary one-command path.
- [ ] Establish the exact command-definition contract independently of routing: truthful context-free and contextful handler call shapes with a runtime-visible context mode, `defineCommand(...)`, private-registry `cliOption(...)`/`cliPositional(...)` annotations, four status-specific schemas, framework usage-error alternatives, bodyless/data-bearing outcome typing, command-level renderers, and the explicit raw definition variant. The review surface is public types and executable README fixtures, not a compatibility layer over `ClinkrGroup`.
- [ ] Build the canonical private lazy topology and source-composition module. Adapt filesystem and narrow scoped-callback programmatic sources into immediate-child scopes; validate strict module and metadata shapes, canonical names/aliases/reserved names, absolute directories, and disjoint source ownership; reject duplicate commands, command/group collisions, and every shared group path with two-source diagnostics; expose no public node, provenance, publication, or cache lifecycle machinery.
- [ ] Build the single `ClinkrApp` runtime over that topology. One navigator resolves execution, help, schema, and completion; selected definitions load transactionally with shared in-flight work, app-lifetime success caching, retry after failure, and fresh Commander materialization per invocation. Clinkr alone owns request and outcome validation, framework usage alternatives, envelopes, rendering, streams, exit codes, raw dispatch, visible completion setup, the hidden resolver, static/dynamic merge and deduplication, provider-error fallback, format aliases, and exception propagation. The new runtime must not lower into or import the old mutable runtime.
- [ ] Reconcile Foundation to process/package/context bootstrap and prove Brmem as the first production consumer. Match or exceed `colocate-brmem-commands-remove-operations`: retain the route-local `src/cli/` tree, hidden `exec`, command-local contracts and presentation, exact inventory and eager-import guards, and fake-driven scenarios; improve field annotations and truthful context typing; prove packed inventory plus packed execution; delete every Brmem/Foundation temporary adapter before continuing.
- [ ] Rebuild SDK/host composition over the same topology and selection traversal. Decode external extension modules once into an exact discriminated recursive contribution union; preserve each source's topology until mounting; attach diagnostics to scope opening and selected loading; remove flat candidate routing, source override precedence, selection apps, group reconstruction, SDK-owned validation/render synthesis, and completion interception.
- [ ] Prove Objectives as the real-host integration. Match or exceed `colocate-objectives-cli-remove-operations`: retain the recursive `src/cli/objective/` tree, hidden `objective/exec`, command locality, exact inventory and eager-import guards, and fake-driven scenarios; cover human, Markdown, and JSON output, framework and command usage errors, all selected operations, context adaptation, malformed-neighbor isolation, source-collision diagnostics, and import counters at nested depths; delete every Objective-specific compatibility path before broad migration.
- [ ] Migrate remaining standalone/Foundation CLIs and extension callers in dependency order, porting behavior tests rather than prototype-internal tests. Move presentation facts into typed outcome data before removing overrides; preserve raw and progressive-output behavior explicitly; do not let migration needs broaden the production topology or descriptor contracts.
- [ ] Delete the quarantined legacy architecture and make the prohibitions structural: mutable `ClinkrGroup`, old raw model, automatic aliases, per-exit rendering, `ClinkrFailure`, duplicate completion plans, legacy Foundation construction, compatibility descriptor detection, validation escape hatches, parallel route selection, obsolete tests, and obsolete exports.
- [ ] Qualify the reconciled package and representative callers, including packed Clinkr and consumer execution, intact command directories, public subpath boundaries, and directly verified shell-completion instructions; then promote the blessed draft to Clinkr's canonical package README and replace the Objective draft with a provenance pointer.
- [ ] Return the steelthread and rebuild gate lessons to `foundation-readme-driven-pass`, including the rule to rebaseline when a vertical slice validates the product interface but reveals central parallel architecture, then close this Subobjective.

- Generated manifests, filesystem codegen, and single-file bundle support; use a justified programmatic seam or a later dedicated adapter rather than weakening the common filesystem contract.
- Per-command context derivation beyond the homogeneous contextful tree until concrete callers justify another model.
- Unrelated Clinkr utilities or downstream CLI redesign discovered during the rebuild; split those into separately tracked work after discussion.
