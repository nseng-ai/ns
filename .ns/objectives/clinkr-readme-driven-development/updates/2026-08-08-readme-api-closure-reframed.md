# README API Closure Reframed Around Bounded Production Vetting

## Summary

The Objective no longer treats repository-wide caller migration and legacy API deletion as prerequisites for promoting Clinkr's canonical README. The supported modern API may remain at the truthful `/app` public entrypoint while compatibility surfaces continue serving unselected consumers.

Completion now requires representative production evidence rather than wholesale conversion: Brmem as a complete standalone filesystem CLI, a substantial coherent Objectives subtree returning the final documented model directly through the real `ns` host, and one selected output- or interaction-heavy workflow using the final Response and invocation-service model through a supported production host. A selected slice does not count if it depends on legacy exits, per-exit rendering, old confirmation gates, or legacy-to-modern conversion within that slice.

`clinkr-output-and-interaction-model` is a hard completion dependency. Its model must be settled, implemented in the bounded production-vetting set, promoted to the chosen durable documentation, and closed before this Objective promotes the canonical package README or declares the README-driven API complete.

## Objective Impact

The thesis, scope, non-goals, completion criteria, risks, open questions, and roadmap now distinguish API completion from repository cleanup. The former remaining-caller and legacy-deletion rows have been replaced with bounded production-vetting and modern-path isolation gates. Packed-package qualification, truthful README evidence, output/interaction-model closure, README promotion, and the parent process lesson remain required.

This rebaseline preserves meaningful real-code validation while removing accidental closure gates such as deleting Foundation's legacy `defineCli`, `ClinkrGroup`, `/legacy`, compatibility exports, and every old operation contract. Eventual migration and deletion remain valid follow-up work but belong in separate tracking.
