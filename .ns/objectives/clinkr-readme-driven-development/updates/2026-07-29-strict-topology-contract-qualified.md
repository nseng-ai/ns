# Strict Topology Contract Qualified

## Summary

The canonical private recursively lazy topology and source-composition owner is now qualified across filesystem, programmatic, and mixed construction.

Focused contract evidence now proves:

- exact one-function `metadata`, `group`, and async `command` ESM namespaces and exact returned shapes;
- complete command pairs, valid group defaults, root-group rejection, exact topology filenames, ignored support files, and contextual filesystem failures with causes;
- nonblank semantic metadata, canonical route and alias names, self/duplicate-alias rejection, absolute command directories through every public construction form, unique nonblank source labels, and a `completion` reservation confined to the enabled app's root scope;
- in-flight sharing, rejected-promise eviction and retry, successful lifetime caching, per-source independence, route-identity selected-command publication, recursive selected-only loading, and owner-only descendant traversal;
- same-source declaration/mount failures and order-independent cross-source command, group, alias, and default-command collision diagnostics with canonical paths and source labels;
- runtime and compile-time boundary evidence that topology sources, module decoders, cache lifecycle, raw construction, completion planning, stream helpers, testing helpers, and legacy owners remain private or on their named subpaths without freezing the temporary `/app` value surface.

The implementation change is intentionally small: final topology construction now rejects blank or duplicate source labels, app-owned reserved names apply only at the root scope, and selected filesystem `command()` exports must return a Promise. Existing topology, composition, collision, and transactional-cache owners otherwise remain intact.
