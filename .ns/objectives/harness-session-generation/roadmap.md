# Roadmap

## Work

- [x] **Research — Establish enforceable isolated-generation behavior for Claude Code and Codex.** Determine, from pinned CLI behavior and primary documentation/source, which settings preserve native login while suppressing project instructions, user behavioral configuration, tools, skills, MCP, history, and repository context; identify any guarantee each harness cannot enforce. **Blocked by:** none. **Evidence:** source-backed guarantee matrix with probe results in `docs/research/claude-codex-isolated-generation-guarantees.md` (pinned to Claude Code 2.1.206 and Codex 0.136.0). Claude Code isolates fully via `--safe-mode` plus companion flags with native OAuth preserved (`--bare` breaks native login and is disqualified). Codex isolates via `--ephemeral --ignore-user-config` plus `-c` overrides, but four guarantees are unenforceable by flags — no-tools, no ambient `$HOME/.agents/skills`, no global `$CODEX_HOME/AGENTS.md`, and true system-prompt replacement — and must be explicit capability rejections or LBYL preflight failures. Every auth-breaking configuration probed failed explicitly, so the fail-explicitly design rule is implementable as-is.

- [x] **Grilling — Settle the Harness, Session, profile, and turn domain model.** Decide where model selection and execution context live, what a session owns, the exact lifecycle, how `runTurn()` represents one turn, and which constraints are fixed at session creation rather than selectable per call. Preserve the settled direction that concrete harnesses create constrained sessions and `runTurn()` is the primitive. **Blocked by:** none. **Evidence:** initially settled in `updates/2026-07-10-domain-model-and-composition-settled.md`, then deliberately revised after prototype critique in `updates/2026-07-10-production-contract-and-foundation-placement-settled.md`. Current outcomes: Harness remains a domain term with no shared interface or capability discovery; strict isolated-generation and advisory `reading-agent` are fixed single-turn profiles; identity and output mode are fixed at creation; usage is the only result generic; text/structured output is a discriminated union; seven failure kinds retain typed stage/cause and diagnostics; eager create/idempotent close remain; statically unsupported factories are absent.

- [x] **Grilling — Settle unified text-generation composition.** Decide the composed dependency beneath the text-generation module, how direct inference and harness-backed inference fit it without TextGenerator subclasses, and the exact common convenience interaction that creates an isolated session, runs one turn, drains text, rejects empty output, and closes. **Blocked by:** none. **Evidence:** settled with the human alongside the domain-model row; same Semantic Update. Key outcomes: one routing `TextGenerator` implementation (non-generic) composing an injected direct executor and per-call isolated sessions, routing per call by hardcoded wiring policy (no env knob; `PI_DRAFT_HARNESS` retires); a wired-but-unusable harness is an explicit error, never a silent fallback; `maxTokens`/`reasoning` become documented advisory hints; empty output is a session-level failure kind; `PiTextGenerator` dissolves into the routing implementation.

- [x] **Research — Inventory consumer semantics and migration invariants.** Record the exact current behavior of Pi fast draft, Reviews Claude/Codex execution, the direct Pi model generator, command execution channels, authentication assumptions, structured output, usage, cancellation, cleanup, and public surfaces that the redesign must preserve or intentionally change. **Blocked by:** none. **Evidence:** per-consumer inventory with a PRESERVE / CHANGE? / UNDEFINED migration-invariants table in `docs/research/harness-consumer-semantics-inventory.md` (every claim cited `path:line`; pinning tests named per invariant). Key facts: four distinct text-generation surfaces exist (two are structural duplicates of one contract); `draftWithFastText` has zero production call sites and is not in the pi exports map, so steelthread deletion is cheap and the live fast-text consumers are the kernel `TextGenerator` flows; the Reviews runners' argv, parse taxonomy, cleanup ordering, and usage handling are hard-pinned by fake-driven tests; cancellation is a blank slate (declared codes with no producers, no AbortSignal test anywhere); the `ns`-hosted exec channel silently drops env/signal/startupError and locks cwd.

- [x] **Prototype — Exercise the candidate contract with fake Claude and Codex harnesses.** Build a throwaway typed prototype that demonstrates direct inference composition, isolated harness generation, a repository-reading turn, terminal-result draining, failure mapping, and cleanup without optionality leakage or provider-specific caller branches. Use it to compare interface depth and reject shallow layers. **Blocked by:** “Establish enforceable isolated-generation behavior for Claude Code and Codex,” “Settle the Harness, Session, profile, and turn domain model,” “Settle unified text-generation composition,” and “Inventory consumer semantics and migration invariants.”
  - Policy: direct execution once its blockers clear; keep the prototype throwaway — outside package public surfaces and exports maps.
  - Evidence: Objective-owned prototype and interface-depth notes under `references/prototype/`; its focused typecheck and 12 fake-driven tests pass. The critique in `references/prototype/CRITIQUE.md` narrows the verdict: the prototype validates type composition, profile-specific creation, usage covariance, routing ownership, and several shallow-layer rejections, but its invented process protocol is not real CLI, lifecycle, command-termination, or migration-conformance evidence. No package exports or live consumers changed.

- [x] **Grilling — Reconcile the prototype critique and settle the production contract, ownership, and migration stack.** Resolve profile meaning and naming, lifecycle cardinality, output typing, unsupported-profile surfaces, failure-stage evidence, command termination, package layering, and stack order. **Blocked by:** none. **Evidence:** interactive grilling decisions recorded in `updates/2026-07-10-production-contract-and-foundation-placement-settled.md`: advisory `reading-agent`; initial single-turn profiles; non-generic discriminated output with usage as the only generic; absent statically unsupported factories; seven kinds plus typed stage/cause; breaking foundation exec termination union; cohesive public foundation harness ownership with a private parameterized engine and concrete adapters; substrate-first migration.

- [x] **Task — Replace foundation command results with an exhaustive termination union.** Replace ambiguous `code`/`killed`/optional-`startupError` interpretation with required `exited`, `spawn-failed`, `cancelled`, and `timed-out` arms; make the Node adapter authoritative for cause, preserve stdout/stderr and useful exit/signal evidence, and migrate all callers atomically. **Blocked by:** none.
  - Policy: direct execution as one repository-wide semantic slice; do not preserve compatibility fields and do not widen `NsExecOptions`.
  - Evidence: landed on trunk via PR #3373 (merged 2026-07-11, commit `d1deb4227`). `ExecResult` in `ts/packages/infra/foundation/src/primitives/command.ts` is the required discriminated union with `exited`, `spawn-failed`, `cancelled`, and `timed-out` arms, every arm preserving stdout/stderr plus exit/signal evidence; the Node adapter (`ts/packages/infra/foundation/src/exec/index.ts`) is authoritative for cause. Focused tests cover before-spawn and in-flight cancellation, timeout with SIGTERM→SIGKILL escalation, spawn failure, ordinary nonzero exit, and output preservation (`test/integration/exec/exec-run-command.test.ts`, `test/isolated/exec/exec-run-command-lifecycle.test.ts`, `test/exec/unit/exec.test.ts`). Callers migrated atomically in the same commit — kernel `ctx.exec` re-exports the union and legacy `killed`/`startupError` exec semantics are gone — and `NsExecOptions` was not widened (still no per-call env or AbortSignal; `NsCommandExecApi` still refuses a foreign cwd).

  - Policy: direct execution; routing policy stays in host wiring, not foundation global truth or an environment knob.
  - Evidence: direct and isolated routing tests, invalid/empty/failure behavior, unconditional close, legacy model-selection compatibility, and one live consumer no longer owning harness mechanics.
