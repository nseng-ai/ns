# Roadmap

## Work

- [x] **Research — Establish enforceable isolated-generation behavior for Claude Code and Codex.** Determine, from pinned CLI behavior and primary documentation/source, which settings preserve native login while suppressing project instructions, user behavioral configuration, tools, skills, MCP, history, and repository context; identify any guarantee each harness cannot enforce. **Blocked by:** none. **Evidence:** source-backed guarantee matrix with probe results in `docs/research/claude-codex-isolated-generation-guarantees.md` (pinned to Claude Code 2.1.206 and Codex 0.136.0). Claude Code isolates fully via `--safe-mode` plus companion flags with native OAuth preserved (`--bare` breaks native login and is disqualified). Codex isolates via `--ephemeral --ignore-user-config` plus `-c` overrides, but four guarantees are unenforceable by flags — no-tools, no ambient `$HOME/.agents/skills`, no global `$CODEX_HOME/AGENTS.md`, and true system-prompt replacement — and must be explicit capability rejections or LBYL preflight failures. Every auth-breaking configuration probed failed explicitly, so the fail-explicitly design rule is implementable as-is.

- [x] **Grilling — Settle the Harness, Session, profile, and turn domain model.** Decide where model selection and execution context live, what a session owns, the exact lifecycle, how `runTurn()` represents one turn, and which constraints are fixed at session creation rather than selectable per call. Preserve the settled direction that concrete harnesses create constrained sessions and `runTurn()` is the primitive. **Blocked by:** none. **Evidence:** settled with the human in an interactive grilling session; decisions recorded in `updates/2026-07-10-domain-model-and-composition-settled.md`. Key outcomes: Harness is a domain term (no shared interface, no capability discovery); profiles are fixed guarantee sets — strict isolated-generation (Claude-only, single-turn) and read-only-agent (renamed from workspace-agent); sequential multi-turn base contract; identity at creation, content per turn; eager create/idempotent close; branded full-fidelity exec channel routing around `ctx.exec`; caller-agnostic harness-native auth; seven-kind failure union with first-class cancelled/timed-out; `TurnResult<TUsage>` with a common token-core bound; finite timeouts; terminal results only (no streaming).

- [x] **Grilling — Settle unified text-generation composition.** Decide the composed dependency beneath the text-generation module, how direct inference and harness-backed inference fit it without TextGenerator subclasses, and the exact common convenience interaction that creates an isolated session, runs one turn, drains text, rejects empty output, and closes. **Blocked by:** none. **Evidence:** settled with the human alongside the domain-model row; same Semantic Update. Key outcomes: one routing `TextGenerator` implementation (non-generic) composing an injected direct executor and per-call isolated sessions, routing per call by hardcoded wiring policy (no env knob; `PI_DRAFT_HARNESS` retires); a wired-but-unusable harness is an explicit error, never a silent fallback; `maxTokens`/`reasoning` become documented advisory hints; empty output is a session-level failure kind; `PiTextGenerator` dissolves into the routing implementation.

- [x] **Research — Inventory consumer semantics and migration invariants.** Record the exact current behavior of Pi fast draft, Reviews Claude/Codex execution, the direct Pi model generator, command execution channels, authentication assumptions, structured output, usage, cancellation, cleanup, and public surfaces that the redesign must preserve or intentionally change. **Blocked by:** none. **Evidence:** per-consumer inventory with a PRESERVE / CHANGE? / UNDEFINED migration-invariants table in `docs/research/harness-consumer-semantics-inventory.md` (every claim cited `path:line`; pinning tests named per invariant). Key facts: four distinct text-generation surfaces exist (two are structural duplicates of one contract); `draftWithFastText` has zero production call sites and is not in the pi exports map, so steelthread deletion is cheap and the live fast-text consumers are the kernel `TextGenerator` flows; the Reviews runners' argv, parse taxonomy, cleanup ordering, and usage handling are hard-pinned by fake-driven tests; cancellation is a blank slate (declared codes with no producers, no AbortSignal test anywhere); the `ns`-hosted exec channel silently drops env/signal/startupError and locks cwd.

- [x] **Prototype — Exercise the candidate contract with fake Claude and Codex harnesses.** Build a throwaway typed prototype that demonstrates direct inference composition, isolated harness generation, a read-only workspace turn, terminal-result draining, failure mapping, and cleanup without optionality leakage or provider-specific caller branches. Use it to compare interface depth and reject shallow layers. **Blocked by:** “Establish enforceable isolated-generation behavior for Claude Code and Codex,” “Settle the Harness, Session, profile, and turn domain model,” “Settle unified text-generation composition,” and “Inventory consumer semantics and migration invariants.”
  - Policy: direct execution once its blockers clear; keep the prototype throwaway — outside package public surfaces and exports maps.
  - Evidence: Objective-owned prototype and interface-depth notes under `references/prototype/`; its focused typecheck and 12 fake-driven tests pass. The critique in `references/prototype/CRITIQUE.md` narrows the verdict: the prototype validates type composition, profile-specific creation, usage covariance, routing ownership, and several shallow-layer rejections, but its invented process protocol does not prove real CLI conformance, enforceable Claude read-only behavior, multi-turn lifecycle, timeout/cancellation classification, or migration compatibility. No package exports or live consumers changed.

- [ ] **Research — Establish enforceable read-only-agent and native-continuation behavior.** Determine whether Claude Code can enforce repository-aware read-only execution rather than merely receive a non-mutation prompt, and inventory the real Claude/Codex continuation mechanisms needed for sequential turns. Decide from evidence whether the production base contract stays sequential multi-turn, starts single-turn, or needs a narrower profile name/guarantee. **Blocked by:** none.
  - Policy: direct execution for source research and read-only local CLI probes; do not settle the contract in the research slice.
  - Evidence: source-backed guarantee matrix and probe transcripts for read-only containment, native session/history behavior, close/resource ownership, and failed/cancelled-turn continuation semantics.

- [ ] **Research — Establish the full-fidelity command and transport prerequisites.** Compare the required harness channel with the real Node and ns command channels; determine how startup failure, caller cancellation, timeout, process-group termination, cwd/env/stdin, binary resolution, and stdout/stderr evidence can be represented without leaking schema or lifecycle semantics into a subprocess interface. Define how Reviews receives a distinct harness-exec dependency without replacing unrelated gateway channels. **Blocked by:** none.
  - Policy: direct execution for code inventory, focused fake/adapter experiments, and a decision dossier; widening `NsExecOptions` remains out of scope unless the human reopens that decision.
  - Evidence: source-cited channel matrix, focused behavior tests or throwaway probe, and a recommended internal gateway shape with unresolved platform changes named explicitly.

- [ ] **Grilling — Reconcile the production contract, placement, curated surfaces, and migration stack.** Using the prototype critique, importer/dependency evidence, and the two prerequisite research rows, settle single- versus multi-turn lifecycle and concurrency, text/structured result typing, static unsupported-profile absence versus runtime preflight failure, failure-stage evidence needed for Reviews compatibility, internal exec seam, package ownership, curated exports, routing-policy injection, canonical `TextGenerator` ownership, and independently valid fast-draft/Reviews migration slices. **Blocked by:** “Establish enforceable read-only-agent and native-continuation behavior” and “Establish the full-fidelity command and transport prerequisites.”
  - Policy: decisions settle with the human; a runner step may assemble evidence but must not decide contract semantics, placement, exports, or staging.

- [ ] **Task — Crystallize the resolved design into execution-ready roadmap slices.** Replace the emptied Frontier with implementation work for the shared contract, Claude/Codex conformance, fast-draft steelthread, Reviews migration, documentation, and final compatibility evidence; preserve unresolved newly visible questions as new Question Rows rather than guessing. **Blocked by:** “Decide placement, curated surfaces, and the migration stack.”
  - Policy: parent tracking work through `objective-update` between steps, not a runner subagent step; the implementation rows it produces should be runner-sized with row-level evidence.
