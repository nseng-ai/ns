## Work

- [x] Inventory and classify every production whole-payload input path before changing interfaces. Separate Clinkr framework `--input-json`, SDK command-owned JSON payloads, interactive line input, and raw-command ownership. Confirm whether any shared non-JSON whole-payload consumer remains after portable Saved Plan save is removed, and record any exception rather than widening the shared seam silently. Evidence: `docs/conventions/clinkr-whole-payload-input-inventory.md` inventories the production paths and confirms that all consumers of the shared Clinkr/SDK whole-payload surface are finite JSON requests after the planned portable Saved Plan deletion; retained arbitrary Brmem/Handoff content is command-owned.
- [x] Delete the portable Saved Plan save path: remove the `enriched-plan-save` skill and Harness Overlays, `enriched-plan exec save`, its `--stdin` and `--content-file` modes, skill-exposure/parity registration, command-specific tests, and stale documentation. Retain and verify Pi `/ns:plan:save`, `/ns:plan:grill-and-save`, `write_saved_plan_file`, `writeSavedPlanFile()`, and Saved Plan read/selection/attachment behavior. Rename retained Pi implementation files if their names would otherwise preserve the deleted workflow identity. Evidence: runner checkpoint `6feddb36a5889f448b408296ebef685d706816dd` removes the portable path and renames the retained Pi modules to `saved-plan-commands`; focused parent verification passed 92 plan and Pi command tests.
- [x] Replace general whole-stream input on the bounded modern path with the smallest finite JSON-specific contract. Prefer a supplied JSON text value over a reader callback unless the inventory proves lazy acquisition is needed. Keep JSON parsing, schema validation, source-conflict checks, and command-specific errors with Clinkr or the owning command. Remove ambient process-stdin fallback from embedded execution and delete obsolete generic `readStdin`/`stdin()` surfaces and tests where no compatibility owner remains. Evidence: PR #4166 first migrated Clinkr, Foundation, SDK, Extension Kit, PR Feedback, and Reviews to finite JSON input; its follow-up correction makes Clinkr the public owner of reusable inline/file/host source selection plus JSON parsing/schema validation, renames the lazy host capability to `readJsonInput`, and removes the Extension Kit helper surface.
- [x] Keep interaction semantic and host-owned. Preserve only demonstrated confirmation and selection operations; use strict fakes in tests, `ctx.ui` in Pi, and an optional standalone rich-library adapter or documented adapter proof. Do not expose terminal streams, line readers, raw mode, key events, cursor state, or resize behavior through shared command types. Evidence: runner checkpoint `710a8f06b03cced1d40b3da207228610ac6d163f` makes every ns host provide confirmation and selection with named results, makes Pi delegate only to `ctx.ui`, and reports an explicit error when the requested UI operation is unavailable; parent-focused verification passed 49 host tests. Clinkr is now the canonical owner of `ConfirmationResult` (including `cancelled`) and `SelectionResult<T>`; the SDK reuses those result types, and a missing host capability remains an error.
- [x] Make structured output and rendering capability explicit per invocation. Preserve standalone process-backed adapters, provide capture sinks and non-ANSI capability for tests and Pi, sanitize terminal controls at the Pi presentation seam, and avoid introducing a mandatory semantic Response/event protocol. Decide separately whether Pi rejects raw commands or supports their existing byte sinks based on the actual exposed-command inventory. Evidence: runner checkpoint `fb3df81e86292c4943480147b8dd1c9fc428284f` gives Pi explicit invocation-owned output sinks and `canEmitAnsi: false`, sanitizes terminal controls at presentation, and preserves downstream raw byte sinks; parent-focused verification passed 51 host tests. Later review established that this was a safety increment rather than the final abstraction: Pi still exposes flattened terminal stream names and can inherit physical TTY caps.
- [ ] Replace flattened stdout/stderr on the bounded structured invocation path with the smallest higher-level presentation seam: primary durable result rendering (`renderResult`) and unclassified auxiliary human text (`echo`), or equivalently precise existing Clinkr-owned names. Adapt standalone execution to stdout/stderr, Pi to deferred per-invocation capture, and tests to strict local capture. Classify touched writes instead of mechanically renaming progress, notifications, rich messages, interaction, or returned failures. Preserve raw-command byte sinks and explicitly account for compatibility consumers such as usage-error detection, Flow submit recovery, traces, and completion hooks.
- [ ] Make structured progress host-owned in Pi. Migrate the bounded textual-phase users (`flow changes`, `flow autobranch`, `flow autoslot`, and `flow generate-pr-inventory`) so transient phase text reaches Pi status rather than deferred echo. Prevent structured phase commands (`flow cp`, `flow submit`, `flow land`, and `flow squash-stack`) from also emitting terminal settled frames into Pi capture. Supply fully settled non-TTY capabilities so inherited physical TTY caps cannot select `log-update` or ambient process writers.
- [ ] Qualify the reduced surface end to end. Cover standalone finite JSON request input; fake-driven request, presentation, progress, and interaction behavior; Pi success and failure presentation; Pi confirmation or selection; explicit no-UI behavior; no ambient process stdin/stdout/stderr during embedded structured execution; fully settled non-TTY and non-ANSI rendering; no transient or duplicate progress in final output; control-sequence sanitization; compatibility metadata and completion hooks; and relevant lifecycle behavior such as idle waiting and stale-context avoidance.
- [ ] Synchronize only the durable documentation warranted by shipped ground truth. Update the relevant Clinkr, Foundation, SDK, Pi, and workflow docs to describe finite JSON request input, semantic interaction, invocation-scoped output, and host ownership; remove stale portable Saved Plan guidance. Add or update CONTEXT.md only after implementation establishes vocabulary.
- [x] Write a final follow-up document on future directions. Record semantic Response/event modeling, richer terminal adapters, streamed progress/notices, raw-command or PTY virtualization, and additional hosts such as MCP. For each direction, name the concrete evidence that would justify reopening it and state that it is not part of the current supported surface or this Objective's completion gate. Evidence: runner checkpoint `db712cd98d01865dc89b35cf531869c3ab8bb830` adds and indexes `docs/follow-ups/2026-08-08-clinkr-invocation-future-directions.md`, reconciles the MCP analysis, and passes default `just` with 6,371 tests.

## Parked

- A unified Request/Response/Progress/Notice/Elicitation ontology.
- `ClinkrResponse`, `ClinkrFinalPresentation`, or a general event stream absent a concrete consumer that cannot use invocation-scoped output capture.
- Arbitrary rich terminal libraries inside Pi; use Pi runtime extension UI capabilities instead.
- PTY, raw-mode, key-event, full-screen, cursor, resize, and terminal-session virtualization.
- Third-host generalization, including MCP, until a concrete production consumer exists.
- Comparative framework research unless a specific implementation decision cannot be made from current consumers and adapters.
- Repository-wide migration or deletion of unrelated legacy Clinkr APIs.
