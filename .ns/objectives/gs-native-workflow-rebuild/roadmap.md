# Roadmap

## Work

- [x] Initial single-worktree architecture and contract baseline — revalidated gh-stack v0.1.0, accepted ADR 0061's GS-native ownership boundary, and reshaped the GS README around the everyday loop, exact version policy, observed postconditions, outcome classes, forward recovery, and Flow independence.
  - Evidence: `docs/research/gh-stack-v0.1.0-workflow-baseline.md` captures reproducible help and disposable-repository observations. Later source and incident evidence establishes that this baseline did not characterize linked-worktree metadata or lock scope, so the completed historical work is now qualified rather than treated as the full lifecycle baseline.
- [~] Provider-worktree architecture correction — experimentally characterize v0.1.0 across linked worktrees; define stable provider-worktree ownership, shared-ref versus private-state authority, cross-worktree concurrency and recovery policy, and safe Slot composition. `ns gs list` now reads the invoking worktree's Git-resolved provider state with explicit provenance; add a superseding ADR only if the remaining experiments materially change accepted architecture.
  - Evidence: `docs/research/gh-stack-v0.1.0-linked-worktree-inventory.md` and real-adapter tests prove distinct private Git directories over one common Git directory, divergent or missing current-worktree metadata over shared refs, Git-resolved state location, and explicit inventory provenance without private-state lifecycle mutation. Independent provider locks, mutating public behavior from owning and peer worktrees, stable ownership lifetime, recovery policy, and safe Slot composition remain open.
- [~] GS-native restack-resolve vertical slice — the single-worktree provider/recovery contract and implementation remain useful, but revalidate wrong-worktree invocation, initiating-worktree recovery, branch occupancy, peer shared-ref mutation, and independent provider locks before finishing its portable skill and Pi surface. Preserve human escalation, no implicit abort, scoped observed postconditions, and forward-only recovery. Trunk fetching/integration and all push/GitHub effects remain deferred to reconciliation.
  - Evidence: preserve the focused single-worktree tests and add linked-worktree scenarios proving the provider-worktree boundary. The thin `/ns:gs:restack-resolve` Pi router implementation now exists, but it awaits linked-worktree revalidation and does not complete the slice. The earlier contract is insufficient to establish cross-worktree safety or repository-wide serialization.
- [ ] Native autobranch vertical slice — promote dirty-trunk bootstrap and dirty-tracked-top extension from the provisional single-worktree skill evidence into `ns gs`. Define tracked-top relative to the current provider worktree, distinguish shared branch/checkpoint creation from worktree-local provider establishment, and refuse branches tracked only in a peer worktree.
  - Evidence: staged, unstaged, untracked, and mixed dirtiness; owning versus peer worktree invocation; missing or divergent local provider state; unsupported states; and post-mutation ambiguity pass without private-state access or Flow imports.
- [ ] Preparation loop and optional autoslot vertical slices — implement GS-owned changes and checkpoint workflows command by command, keeping Git checkpoint durability distinct from provider-worktree readiness. For a new one-branch stack, move before destination provider initialization only if public-command experiments prove safe adoption without ref rewriting. Refuse existing multi-layer branch-level movement until complete-stack establishment and stale-source disposition are proven.
  - Evidence: Slots-absent behavior is covered; destination completion proves branch, checkpoint, cleanliness, complete provider topology, and provider-worktree identity. Slot placement followed by failed provider establishment is a known partial failure, while unsupported multi-layer movement refuses before provider mutation.
- [ ] Reconciliation contract — experimentally settle `gh stack sync` behavior across clean, behind-trunk, rebase, conflict, unpublished, published, remote-changed, untracked, and partial-failure states from one explicit provider worktree, including stale or divergent peer metadata and concurrent peer operations. Decide the public command shape and whether submit or land may invoke reconciliation automatically; update the README before implementation.
  - Evidence: the resulting implementation and recovery contract names observed shared-ref, current-worktree metadata, push, PR-link, peer-staleness, and partial-mutation behavior rather than relying on command descriptions.
- [ ] GS-native submit — implement checks, checkpointing, provider-worktree topology and shared-ref SHA reverification, the settled reconciliation policy, native provider submission, authoritative GitHub branch-to-PR reconciliation, and structured partial-effect reporting. Report current-worktree provider updates separately from shared Git and GitHub effects; do not imply peer metadata reconciliation. Establish GS-owned submit Points and recovery behavior where the contract requires them.
  - Evidence: tests cover new and existing PRs, failed checks, provider failure, missing or duplicate PR identities, partial publication, metadata preparation failure, and partial metadata application.
- [ ] GS PR inventories — implement the GS-owned focused and submit-integrated inventory outcomes with explicit destructive authorization and deterministic provenance, without importing Flow behavior at runtime.
  - Evidence: title/body preparation and application tests prove new-versus-existing selection, complete replacement policy, no-edit preparation failure, and bounded partial-apply recovery data.
- [ ] GS-native land — settle and implement provider-worktree/GitHub topology reconciliation, readiness preflight, safe merge or queue semantics, partial-prefix completion, owner-scoped post-merge provider maintenance, optional Slot cleanup, and honest peer-staleness reporting. Omit Graphite-specific continuation or stack surgery unless provider evidence establishes a native outcome; never free a provider-owning Slot while its local model remains required.
  - Evidence: linked-worktree scenarios cover complete landing, readiness refusal, merge or queue ambiguity, failure after a landed prefix, provider disagreement, peer metadata staleness, owner-Slot cleanup refusal/failure, and dry-run behavior.
- [ ] Pi catalog reconciliation — after command-sized slices have shipped their native skills and `/ns:gs:*` surfaces, reconcile registration, presentation, recovery, and parity coverage across the settled catalog. Retire only provisional `/ns:flow:gs:*` skill-backed surfaces that completed GS slices replace; do not alter Flow's native GT CLI or Pi surfaces.
  - Evidence: Pi routing, parity, required-skill, cold-import, and startup tests pass for the settled GS catalog without deferring missing per-command host behavior to this final pass.
- [ ] Everyday-loop proof and documentation reconciliation — exercise the loop from preparation through landing in both the provider worktree and supported Slot scenarios, close remaining command/API inconsistencies, and synchronize the GS README, GS context, Context Map, provider capability documentation, and relevant Pi documentation with shipped behavior.
  - Evidence: same-worktree and linked-worktree scenarios cover wrong-worktree invocation, stale or absent peer metadata, shared-ref/private-state divergence, concurrency refusal or bounded handling, initiating-worktree recovery, and safe owner-Slot cleanup. Focused package, scenario, integration, Pi, TypeScript architecture, and repository validation checks pass; bounded dependency searches confirm GS has no Flow runtime edge; Flow remains otherwise untouched.

## Parked

- Flow deprecation, archival, deletion, package removal, command removal, or Pi-surface retirement.
- Exact replacements for Graphite-shaped latest-commit extraction and stack squash without a demonstrated GS-native need.
- A universal stack-provider abstraction or command-parity layer spanning Graphite and gh-stack.
- Support for additional gh-stack versions without a separate evidence-backed widening decision.
- Cold external-consumer installation and packaging qualification beyond repository-local validation.
- Provider-private state mutation, copying, merging, or lifecycle behavior based on direct reads of any worktree's private `gh-stack` file.
- General complete-stack ownership transfer until public provider adoption, source disposition, PR-association preservation, and shared-ref safety are experimentally proven.
- Standalone plain-Git push behavior unless a GS recovery scenario proves it necessary.
