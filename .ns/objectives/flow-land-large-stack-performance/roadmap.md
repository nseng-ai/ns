# Roadmap

## Work

- [x] Add Flow land external-call telemetry for Graphite, `gh`, and GitHub API interactions.
  - First milestone. Capture timing, status, category, and call counts. Reserve an optional per-call quota field in the event schema and populate it from the static cost model of known `gh` command shapes; live quota capture (`GH_DEBUG=api` header parsing, direct-API headers) is a later fidelity level, not part of this milestone. Expose structured in-process events, concise verbose summaries, and lightweight XDG/state JSON per-run diagnostics. Evidence: targeted tests cover emitted facts, log shape, and the reserved quota field.
  - Done via local branch evidence (`impl-flow-land-external-call-telemetry`, `flow-land-per-run-diagnostics`): event schema and sink in `ts/packages/capabilities/flow/src/land/stack/external-call-telemetry.ts` wired through `withCommandStreaming`/`LandStackCommandStream`; per-run diagnostics collector in `external-call-telemetry-run.ts` writing schema v1 JSON to `$XDG_STATE_HOME/sdl/flow/land/runs/<runId>.json` (fallback `~/.local/state/...`); `--verbose` telemetry summary in `sdl flow land`. Durable entries persist only transport/category/operation/elapsed/status/exit/quota estimate — no command strings, PR titles/bodies, or branch names. Static quota model covers Graphite and `gh`; the schema supports a `github-api` transport whose emitter wiring is deferred until a direct API path exists. Targeted Vitest plus full `just` passed on both slices.

- [~] Reduce Graphite maintenance cost where measurements justify it.
  - Investigate rolling-frontier maintenance, avoiding repeated `gt restack --upstack` over the remaining stack, and replacing full topology rereads with targeted safety checks where safe.
  - First optimization landed via local branch `flow-land-large-stack-performance/targeted-graphite-refresh`: required next-landing maintenance now uses branch-only `gt restack --branch <branch> --only`, while optional descendant maintenance keeps `--upstack`. Fake-backed counts improved from linear-11 154→145 total calls and linear-25 336→313 total calls by skipping downstream post-restack SHA rereads for branch-only restacks. Real wall-time improvement still requires a human-driven large-stack run.
  - Second optimization landed via a Graphite PR stack (`flow-land-pr-node-id` → `flow-land-trunk-fetch` → `flow-land-lease-push-retarget` → `flow-land-graphql-merge`, reconciled by `flow-land-perf-baselines`): the required linear landing path no longer runs any per-PR `gt` beyond `gt delete` + branch-only `gt restack`. Before→after command shapes per landed required-path PR — mid-loop trunk advance `gt get <next> --downstack --force` → `git fetch --quiet --no-tags origin refs/heads/<trunk>:refs/heads/<trunk>` (fast-forward-only; verbatim `gt get` fallback when trunk is checked out; halt on non-FF); metadata resync `gt submit --update-only --force` (plus its pre-submit `gh pr view` + `git rev-parse`) → `git push --force-with-lease=refs/heads/<b>:<preRestackSha>` (lease seeded from the pre-restack backup-ref snapshot; lease-rejected → halt with backup-recovery hint) plus a GraphQL `updatePullRequest` base retarget. Cumulative fake-backed Graphite invocations dropped linear-11 54→34 and linear-25 124→76 (total calls 145→119 and 313→259); the optional-descendant path keeps `gt get`/`gt submit`. Cleanup guards, backup refs, and the serial safety model are unchanged; real Graphite wall-time still requires a human-driven run.
  - Mid-run staleness rationale: dropping per-PR `gt submit` leaves Graphite's server-side metadata for the branches being landed stale during a run, but those branches are merged and deleted by run end, so the staleness is transient and self-resolving. The retained `gt submit` on the optional-descendant path resyncs the surviving branches that outlive the run; a mid-run halt is reconciled with `gt sync` per the halt guidance.
- [~] Reduce GitHub/`gh`/API call volume while preserving quota visibility and merge safety.
  - Investigate batched PR fact loading and avoiding redundant reads: the current per-PR sequence fetches overlapping PR facts three times (pre-merge `gh pr view` gate, `gh pr merge`'s internal PR-finder query, post-merge `gh pr view` verification). A direct GraphQL merge path is a known-viable option — `cli/cli` source confirms `gh pr merge` is one finder query plus a `mergePullRequest` mutation with `expectedHeadOid` matching `--match-head-commit` — but adopt it only if baseline evidence justifies it, with parity test coverage.
  - Policy: read-path batching/dedup is direct execution once baseline evidence exists; replacing the merge primitive is steer-first regardless of evidence.
  - First read-path optimization landed via local branch `flow-land-large-stack-performance/post-merge-pr-cache`: large-stack preflight PR fact loading now uses one `gh repo view` plus one `gh api graphql` batch query for stacks over two branches, while small stacks keep per-branch `gh pr view`. Fake-backed counts improved from linear-11 163→154 total calls (github-cli 54→45) and linear-25 359→336 total calls (github-cli 124→101). `gh pr merge` and strict post-merge verification remain unchanged; static quota cost is intentionally conservative and rises by one due to per-branch PR connection accounting.
  - Merge-primitive optimization landed via `flow-land-graphql-merge` (node ids from `flow-land-pr-node-id`), reconciled by `flow-land-perf-baselines`: the per-PR `gh pr merge --squash` plus its standalone post-merge `gh pr view` verification are replaced by one GraphQL `mergePullRequest` mutation (`expectedHeadOid`/`commitHeadline`/`commitBody` parity with `--match-head-commit`/`--subject`/`--body`) whose response carries the verification payload for the strict MERGED/base/head checks; a single `loadPr` fallback runs only on an exit-0-malformed response. Base retarget moved off `gt submit` onto a GraphQL `updatePullRequest` mutation (`flow-land-lease-push-retarget`). Both mutations run through capability-kit `github/pr-mutations.ts` and cost `{graphqlRequests: 1, rateLimitCost: 1}` each (the old `gh pr merge` static cost was 2). This steer-first merge-primitive change was authorized as its own stack. Cumulative fake-backed GitHub GraphQL requests dropped linear-11 56→34 and linear-25 126→76; static rate-limit cost 66→44 and 150→100; github-cli calls 45→34 and 101→76. Strict PR/head checks and `--force-with-lease` safety are retained; real wall-time still requires a human-driven run.
- [~] Reduce local git/ref subprocess volume where measurements justify it.
  - Investigate batching branch existence/SHA reads, backup ref writes/deletes, and other per-branch local probes without weakening backup or cleanup guarantees.
  - First optimization landed via local branch `flow-land-large-stack-performance/gh-pr-view-cache`: Flow land preflight now reuses the existing repo-discovery local-branch tip inventory for branch presence/SHA checks instead of issuing per-landing-branch `show-ref`/`rev-parse` subprocesses. Fake-backed counts improved from linear-11 205→183 total calls (git 97→75) and linear-25 457→407 total calls (git 209→159), with strict merge-time PR/head verification and backup/cleanup gates retained.
  - Second optimization landed via local branch `flow-land-large-stack-performance/gh-read-path-dedup`: backup snapshotting now batches exact-SHA reads and backup-ref writes with one `for-each-ref` and one local `git fetch`, replacing per-branch `rev-parse`/`update-ref` loops while preserving rotation, stale-ref pruning, backup refs, and failure-before-merge behavior. Cumulative fake-backed counts now stand at linear-11 163 total calls (git 55) and linear-25 359 total calls (git 111). Follow-up candidates remain stale backup deletion and post-restack guard reads.
