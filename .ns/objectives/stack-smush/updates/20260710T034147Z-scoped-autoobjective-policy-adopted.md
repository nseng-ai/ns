# Scoped Autoobjective Policy Adopted

## Summary

The user asked to make this record an autoobjective ready for autonomous execution.
Because Stack Smush is a pre-Crystallization ideation Objective — and autoobjective
layers with wayfinding only after Crystallization, since Question Rows are decisions,
not autonomous slices — full conversion was rejected in favor of scoped autonomy,
confirmed explicitly by the user:

- `## Definition of Progress` and `## Runner Policy` were added to `objective.md`.
- Autonomous Objective Runner steps are limited to open, unblocked, agent-alone rows
  (research and task rows); grilling and prototype rows always escalate to live
  exchange.
- Git/validation bounds, confirmed by the user: runner steps work on a feature
  branch (never `master`), commit one coherent slice per step, validate with `just`
  when code changed; no PR submission, push, or external writes unless explicitly
  requested in-session.
- The Graphite slicing-mechanics survey row gained row-level `Policy:`/`Evidence:`
  prose as the one autonomous target currently on the Frontier.

## Objective Impact

The record is now execution-friendly for `objective-next` and a valid scoped target
for `ns objective exec runner-step` on agent-alone rows. The ideation shape is
unchanged: the Frontier, its grilling/prototype rows, and the Destination stand as
before. At Crystallization, execution rows must be reshaped runner-sized before
autonomous pursuit continues — the Runner Policy states this gate durably.

## Follow-Ups

- Run the Graphite slicing-mechanics survey as the first autonomous runner step.
- At Crystallization, reshape execution rows runner-sized and revisit whether the
  scoped-autonomy language in `## Runner Policy` should widen.
