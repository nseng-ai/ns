## Objective Impact

This completes the roadmap's runtime workspace dependency triage row. The package strategy remains Pi-style: publish first-party runtime packages where feasible, reserve bundle-inline for concrete exceptions, and exclude host/internal/dev-only packages from the required checkout-free CLI runtime.

The main follow-on design pressure is now explicit: the loader rewrite cannot simply carry every current checkout alias into the published runtime. It should resolve installed package JS for published runtime packages and should deliberately gate or remove aliases for excluded/deferred packages, especially `@ns/ccc`.

## Follow-Ups

- In the loader rewrite, resolve `@ns/kernel`, `@ns/capability-kit`, `@ns/flow`, and already-public capability packages from installed package JS instead of absolute checkout `.ts` paths.
- Decide during the loader/build slice whether `@ns/kernel` itself becomes the published CLI package or whether a published wrapper supersedes it; either way, the `ns` bin must be publishable.
- Gate, remove, or relocate the current hard-coded `@ns/ccc/{autoslot,land,trunk-pull}` aliases so an Objective-focused checkout-free CLI does not require private ccc source unless ccc is deliberately included in a later package set.
- Keep `@ns/pi`, `@internal/pi-tools`, `nscc`, and `@internal/typescript-style-guard` out of the mandatory npm CLI runtime unless later evidence records a new product decision.
- Add publish/build metadata for packages classified as publish when the build/bundle slice begins; no manifest or publish changes were made in this triage slice.
