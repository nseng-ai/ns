# Standalone Runtime Publish Setup

## Summary

The standalone runtime package set now has npm publish preparation wired through a shared generated publish-root script instead of relying on raw workspace manifests.

Implementation evidence:

- Added `ts/scripts/prepare-source-publish-package.mjs` to generate `dist/publish/package.json` for source-shipped runtime packages.
- The generator rewrites `workspace:` dependency specs to the selected workspace package versions, rewrites `catalog:` specs to concrete catalog versions, and rewrites private `@nseng-ai/kernel` runtime dependency edges to the public `@nseng-ai/ns` package while copying source files with imports adjusted to `@nseng-ai/ns/kernel/*`.
- `@nseng-ai/capability-kit` and `@nseng-ai/flow` are no longer private.
- Added `publishConfig.access=public`, `pack:local`, and `publish:dry-run` scripts for the runtime package set: `@nseng-ai/capability-kit`, `@nseng-ai/flow`, `@nseng-ai/foundation`, `@nseng-ai/clinkr`, `@nseng-ai/brmem`, `@nseng-ai/branch-context`, `@nseng-ai/handoffs`, `@nseng-ai/objectives`, `@nseng-ai/plans`, `@nseng-ai/pr-feedback`, `@nseng-ai/retros`, `@nseng-ai/reviews`, and `@nseng-ai/slots`.

Dry-run evidence collected locally:

```bash
pnpm --dir ts --filter @nseng-ai/capability-kit run publish:dry-run
pnpm --dir ts --filter @nseng-ai/flow run publish:dry-run
pnpm --dir ts --filter @nseng-ai/foundation run publish:dry-run
```

and the same `publish:dry-run` script for branch-context, handoffs, objectives, plans, pr-feedback, retros, reviews, slots, brmem, and clinkr all reached npm dry-run package validation with public access.

Validation also included:

```bash
just ts-deps-check
just dprint-check
just ts-format-check
just ts-lint
just ts-check
```

## Objective Impact

This completes setup for publishing the standalone runtime packages this Objective intends to publish beyond the bundled `@nseng-ai/ns` CLI package. It makes the package manifests npm-publishable by generated publish roots rather than publishing raw workspace-only metadata.

This does not perform real registry publishes for those packages and does not add release automation; those remain outside the manual v1 registry publish already completed for `@nseng-ai/ns@0.1.0` unless explicitly authorized later.

## Follow-Ups

- If these standalone packages are actually published, run the package `publish:dry-run` immediately before each real publish and publish in dependency order.
- A later hardening slice can replace source-shipped package roots with prebuilt JavaScript package roots if the public package policy requires avoiding `.ts` source in npm artifacts.
- Keep `@nseng-ai/kernel` private; published packages should depend on `@nseng-ai/ns/kernel/*` as generated by the publish-root script.
