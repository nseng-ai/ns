Architecture review — sdl-flow

2026-06-29 · v2 · land-extraction prioritized

Nine deepening opportunities in ts/packages/capabilities/flow, drawn from a four-way deep read of the landing, submit, shared, and autobranch/command subsystems. Each turns a shallow module — interface nearly as wide as its implementation — into a deep one, or relocates a leak back behind its seam. The priority is to extract land as a self-contained deep module behind a one-function seam; five of the nine candidates are the constituent moves that get there.

Everything land lives under src/land/ behind executeStackLanding + registerLandCommand. The rest of flow and CCC depend only on that interface — making land's eventual lift into its own capability package a later, mechanical step.

Problem. Land is the largest, deepest concern in flow yet has no module boundary: dispatch is decided twice, status is a stringly back-channel into the command face, presentation and a 1,225-line god-file are tangled with the rest of shared/, and api.ts leaks 13 land symbols so CCC couples to internals.

Solution. Consolidate all land code under src/land/ behind a narrow interface (executeStackLanding + registerLandCommand + a small typed LandOutcome), with every other module and CCC depending only on that seam.

  • depth: huge land behavior behind one function
  • leverage: CCC + command face learn one interface
  • locality: land bugs concentrate under src/land/
  • the interface becomes the land test surface
  • sets up a clean lift to a land capability package
  • directly executes the objective's land-decomposition rows

Constituent moves — sequence the five land candidates

  1. 2 →Split the god-file so the merge/maintenance/prep phases become nameable internals of the module.
  2. 5 →Typed Graphite seam replaces argv-scripted tests so the module is tested through intent, not command strings.
  3. 6 →One land path collapses the fast-path fork so the module has one entry with one safety guarantee.
  4. 1 →Structured outcomes turn the setStatus back-channel into a typed LandOutcome/LandPhase at the seam.
  5. 9 →Narrow the api seam down to executeStackLanding/registerLandCommand, stopping the 13-symbol land leak to CCC.
Stay inside the objective's guardrails. Land is Flow domain — keep it Flow-owned; do not push it down into @sdl/core/kernel/pi, and keep CCC a consumer, not the owner. Treating src/land/ as a bounded module behind executeStackLanding is the in-objective step; promoting it to a standalone land capability package is a separate, later decision (the objective's open question on a deeper LandingWorkflow). Preserve durable refs/ccc/land-backup/* namespaces.

5 · A typed Graphite seam over the argv strings

Worth exploring ports & adapters ★ land extraction

land-stack/* · autobranch/latest-commit-transaction.ts · command-exec.ts:71–92 · test/unit/land-stack-command-scenarios.test.ts (2,802 lines of argv assertions)

Before — the seam is an argv string

exec("gt", ["submit","--no-interactive","--no-edit", …7 flags])
exec("gt", ["delete", branch, "--force"])
exec("git", ["reset","--hard", parentSha])
exec("git", ["fetch", …, "+refs/ccc/land-backup/*:…"])

No Graphite/Gh gateway with named operations; reorder a preflight read and dozens of tests break though behavior is unchanged. Five exec-API variants are threaded by hand.

After — typed operations behind one seam

graphite.submit(plan)
graphite.deleteBranch(branch) → Deleted | AlreadyAbsent
git.resetHard(sha) · backup.rotate()
in-memory fake = two adapters → a real seam
tests assert intent, not argv

gt delete idempotency lives in the operation, not the generic runner.

Problem. Git/Graphite/gh are scripted as raw exec("git",[…strings]) everywhere; the test surface asserts exact argv order, and normalizeCommandFinish special-cases gt delete / topology-read inside the generic exec helper.

Solution. Introduce a typed Graphite (and gh) gateway with named operations and an in-memory fake; let argv construction and command idempotency live behind it.

  • two adapters (real gt + fake) justify the seam
  • tests assert intent, survive flag/order churn
  • collapses 5 exec-API variants to one
  • idempotency moves out of the generic runner
Aligns with — and should be scoped against — the neutral-infra-gateway-consolidation objective (ADR 0018/0019). That work routes external-tool I/O through @sdl/capability-kit/<domain> gateways and @sdl/graphite. Build the Graphite operations as a Flow-owned consumer of that seam, not a private re-implementation — and respect the graphite-dependency-boundary (runtime code prefers GitGateway).

Top recommendation

★ Priority Extract land as a deep module out of flow

Land is the largest, deepest, least-bounded concern in the package — and the one most worth a real seam. The path is a sequence, not a leap: 2 split the god-file → 5 typed Graphite seam → 6 one land path → 1 structured outcomes → 9 narrow the api seam. Each step is independently shippable and behavior-preserving; together they consolidate land under src/land/ behind executeStackLanding + registerLandCommand. Start with 2 (already a roadmap row) and 5 (the fake-driven seam the objective wants), since they unblock the rest. Candidates 3, 4, 7, 8 deepen submit/autobranch/shared in parallel and don't block the land work.
