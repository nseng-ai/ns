# Success-With-Warnings Rendering Assessed

## Summary

Assessed current success-with-warnings rendering across Flow, CCC autoslot, CCC land, Slot hidden exec surfaces, and the `@sdl/cli-theme` finite result-block primitives. No production refactor is warranted in this slice.

Evidence inspected:

| Surface                                      | Current warning shape                                                                                                                                                                                                                                                                                                                            | Rendering/routing finding                                                                                                                                                                                                            |
| -------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Flow `autobranch` and `branch-latest-commit` | Successful autobranch flows return `warnings: string[]` for non-fatal preparation / cleanup issues; command wrappers emit each warning to stderr before returning an `ok(...)` success result block on stdout. The success summary body can also contain domain-authored cleanliness warning text.                                               | Routing is command-edge policy: non-fatal diagnostics go to stderr, success remains stdout and exit 0. The theme already supplies the success result block; a theme helper would have to own stdout/stderr policy it should not own. |
| CCC standalone/autoslot autobranch path      | `runAutoslotCli` adapts `CommandIo` so warning notifications route to diagnostic output, while final autoslot success/refusal/failure blocks stay CCC-local facades over `@sdl/cli-theme`.                                                                                                                                                       | Autoslot combines autobranch warnings, slot-checkout guardrails, and exit-flag behavior. The warning level owns routing/exit semantics; visual block kind remains a separate CCC decision.                                           |
| CCC land stack                               | `LandingWarning` carries message, optional command details, suggested action, notification action, and `warning`/`info` level. Land successes with warnings keep a success result-block kind, set the final notify level to `warning`, put detailed warning lists in the command stream summary, and use action-first compact notification text. | This is rich domain presentation and policy, not a generic theme primitive. A `success-with-warnings` theme kind would obscure that land is still a successful landing while the host notification severity asks for attention.      |
| Slot hidden `gt exec` stack surfaces         | Hidden exec commands carry warning strings in JSON payloads and sometimes mirror warnings to stderr for cd-directive mode.                                                                                                                                                                                                                       | These are agent/exec payload surfaces, not normal house-style finite result blocks. Styling them would violate the Objective's non-goal around hidden `exec` surfaces.                                                               |
| `@sdl/cli-theme`                             | `ResultBlockKind` is intentionally finite: `success`, `failure`, `refusal`; warning color/glyph support exists through palette/result refusal/status-line primitives.                                                                                                                                                                            | The theme owns visual grammar but not warning routing, severity escalation, exit behavior, or domain warning details. Existing `body`/`guidance` fields are sufficient for callers that need warning prose inside a success block.   |

Decision: keep success-with-warnings handling local to the command family for now. Do not add a `success-with-warnings` `ResultBlockKind`, warning-list renderer, or command-routing helper to `@sdl/cli-theme`. A tiny local helper may be acceptable later within a command family if repeated loops become noisy, but the current loops are trivial and the rich land/autoslot behavior is domain-owned.

## Objective Impact

- Completed the roadmap row for success-with-warnings rendering.
- Reinforced the package boundary: `@sdl/cli-theme` owns result-block layout and warn/success visual primitives; command packages own stderr/stdout routing, notify severity, exit-code policy, warning aggregation, action-first notification text, and domain warning details.
- Left no production code changes because the assessment found no repeated domain-free presentation grammar beyond primitives already present in the theme package.

## Follow-Ups

- Continue with caps-resolution placement assessment next; the warning assessment adds no new theme-package work.
- If future normal human CLI surfaces repeatedly need the same visual-only warning list inside a result block, reassess a narrow presentation-list primitive that excludes routing, severity, and exit policy.
