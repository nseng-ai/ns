# Post-Extraction Duplication Rebaseline

## Summary

Rebaselined the migrated-command duplication analysis against the landed `@sdl/cli-theme` boundary instead of the historical `@sdl/clinkr/theme` paths.

Current live presentation seams inspected:

- `ts/packages/infra/cli-theme/src/result-block.ts`, `status-line.ts`, and `table.ts` now own the shared house-style primitives: finite result block layout, phase status-line grammar, palette/glyph/text helpers, and caps-aware one-line table layout.
- Flow finite command surfaces use `@sdl/cli-theme` directly or through Flow-local facades: `git-result-block.ts`, `autobranch-result-block.ts`, `pending-worktree-result.ts`, and command wrappers for `autobranch`, `branch-latest-commit`, `pull-trunk`, `push`, and `regenerate-pr`.
- Flow streaming surfaces keep sequencing, phase state, transcript tailing, and host-aware caps resolution in `ts/packages/capabilities/flow/src/shared/phase-stream*.ts`, while using theme `statusLine` and text helpers for each row.
- CCC keeps domain-local result-block facades for `autoslot` and `land`; their typed outcome facts map to the shared theme result-block layout only at the CLI edge, preserving ANSI-free Pi command-stream paths.
- Slot has one house-style navigation pilot in `ts/packages/capabilities/slot/src/navigation-presentation.ts` for `slot goto`, while `slot checkout` and `slot gt up/down` still use the legacy plain `renderNavigationFooter` path in `navigation-result.ts` / `operations/gt/navigation.ts`.
- `@sdl/core/text-table` and `@sdl/cli-theme` table primitives are still distinct: the core helper supports simple ANSI styles, multiline continuation rows, optional rules, and display-width measurement; the theme helper accepts styled/plain `Cell`s, clips to terminal caps, supports fill/auto/fixed widths, and returns one physical row per data row.

## Objective Impact

- Completed the rebaseline roadmap row: follow-up decisions now point at `@sdl/cli-theme`, public Clinkr caps/stream seams, and live post-extraction consumers instead of stale `@sdl/clinkr/theme` locations.
- Confirmed the extraction boundary remains sound: `@sdl/cli-theme` owns presentation grammar, while Clinkr owns caps/IO/stream mechanics and command/domain packages own outcome policy, exit/routing semantics, and domain facts.
- Narrowed the likely next Objective implementation work to Slot navigation footer migration. The remaining outcome, warnings, caps, table, and status-to-intent rows should be assessed conservatively before any promotion into the theme package.

## Follow-Ups

- Start with the Slot navigation footer row: extend `navigation-presentation.ts` to cover `slot checkout` and `slot gt up/down` success surfaces, then remove or constrain `renderNavigationFooter` once consumers are migrated.
- When assessing outcome mapping, avoid putting `AutobranchFlowOutcome`, `LandStackFailure`, notify levels, exit-code policy, or Git transcript cause mining into `@sdl/cli-theme`.
- When assessing tables, preserve the distinction between terminal text layout and Markdown output unless a concrete repeated Markdown composition need appears.
