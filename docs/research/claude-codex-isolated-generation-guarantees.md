# Claude Code / Codex Isolated Single-Turn Generation: What Each Harness Can Guarantee

**Researched:** 2026-07-10, for Objective `harness-session-generation` (`.ns/objectives/harness-session-generation/objective.md`).
**Question:** which settings let the Claude Code CLI and the Codex CLI run an isolated single-turn text generation that *preserves the harness's native authenticated login* while *suppressing all ambient behavioral context* — and which guarantees each harness cannot enforce. Design rule: unsupported guarantees must fail explicitly, never silently degrade.
**Pinned versions (verified locally):**

- Claude Code `2.1.206 (Claude Code)` — resolved binary `/Users/schrockn/.local/share/claude/versions/2.1.206` (via the `~/.local/bin/claude` symlink). The interactive zsh `claude` is an alias adding `--verbose --allow-dangerously-skip-permissions --permission-mode auto`, and a cmux shim shadows `claude` earlier on `PATH`; every probe below invoked the resolved absolute binary so neither could contaminate results.
- Codex `codex-cli 0.136.0` — resolved binary `/opt/homebrew/bin/codex` → `/opt/homebrew/Caskroom/codex/0.136.0/codex-aarch64-apple-darwin`.

**Method:** full `--help` surfaces captured from the pinned binaries (primary source for flag semantics at these exact versions); official docs (code.claude.com/docs — cli-reference, settings, memory, iam, headless, agent-sdk/modifying-system-prompts — plus `anthropics/claude-code` CHANGELOG.md for version attribution); the `openai/codex` Rust source at tag `rust-v0.136.0` (file:line citations below are against that tag); and controlled local probes in scratchpad-only temp dirs: planted `CLAUDE.md`/`AGENTS.md` markers ("begin every reply with BANANA-MARKER"), marker-detection questions that do **not** contain the marker string, one-token auth probes, a planted bogus `config.toml`, and before/after listings of `~/.claude/projects`, `~/.codex/sessions`, `~/.codex/history.jsonl`, `~/.codex/session_index.jsonl`. No real user config was mutated; no credential contents were read or printed (the one auth-splitting probe symlinked `~/.codex/auth.json` into a scratch `CODEX_HOME`, removed afterward).

**Confidence labels:** `documented` (official doc/help text), `source-confirmed` (openai/codex source at the pinned tag), `probe-confirmed` (observed on the pinned binary), `uncertain`, `unsupported`.

## TL;DR — the five load-bearing facts

1. **Claude Code `--bare` breaks native login; `--safe-mode` preserves it.** `--bare` (added v2.1.81) help text: *"Anthropic auth is strictly ANTHROPIC_API_KEY or apiKeyHelper via --settings (OAuth and keychain are never read)."* Probe-confirmed: `--bare` under a keychain-OAuth-only login fails explicitly with `Not logged in · Please run /login` (exit 1). `--safe-mode` (added v2.1.169) disables *"all customizations (CLAUDE.md, skills, plugins, hooks, MCP servers, custom commands and agents, output styles, ...)"* while *"Auth, model selection, built-in tools, and permissions work normally"* — probe-confirmed to suppress both project and user CLAUDE.md with native OAuth intact. The isolated profile for Claude Code is built on `--safe-mode`, not `--bare`. Consequence: the existing Reviews Claude runner (`--bare`) only works when `ANTHROPIC_API_KEY`/apiKeyHelper is provided; it cannot use harness-native subscription login.
2. **Codex `--ignore-user-config` is the auth/behavior splitter the contract needs** — help text: *"Do not load `$CODEX_HOME/config.toml`; auth still uses `CODEX_HOME`"* — but it empties **only the user and profile config layers** (`codex-rs/config/src/loader/mod.rs:391-419`). It does **not** suppress project `AGENTS.md` (probe-confirmed leak under today's Reviews profile; fixed by `-c project_doc_max_bytes=0`), does **not** suppress `$CODEX_HOME/AGENTS.md` (loaded unconditionally, `codex-rs/core/src/config/mod.rs:2491` — **no flag or config key gates it at 0.136.0**), and does not touch project/system/admin config layers.
3. **"No tools" is unenforceable on Codex; "no skills" is only partially enforceable.** Claude Code `--tools ""` yields a genuinely tool-less request (probe: model reports 0 tools). Fully isolated Codex still exposes its intrinsic tool set (probe: 15 tools including `exec_command`, `apply_patch`) and still ambient-injects skills: 7 on this machine, reduced to 2 by `-c skills.bundled.enabled=false` — the survivors are the user's `~/.agents/skills`, for which **no disable mechanism exists** (`codex-rs/core-skills/src/manager.rs:157-167` filters only the System scope). Both must be explicit capability rejections on Codex.
4. **Auth and behavior share a root in both harnesses, and naive root-redirection kills login in both.** `CLAUDE_CONFIG_DIR=<fresh>` → `Not logged in` (exit 1) even though credentials live in the macOS Keychain — keychain creds alone are not sufficient; OAuth account state in the config dir gates them. `CODEX_HOME=<fresh>` → explicit `401 Unauthorized` (exit 1). For Codex only, symlinking *just* `auth.json` into a fresh `CODEX_HOME` restores login while dropping every `CODEX_HOME` behavior — config.toml *and* global AGENTS.md (probe-confirmed for config; source-implied for AGENTS.md). That construction is the only complete Codex behavioral isolation.
5. **Every auth-breaking configuration probed failed explicitly** (non-zero exit plus a diagnostic: `Not logged in · Please run /login`, `401 Unauthorized`, typed 400 for auth-restricted models). No silent degradation was observed — the "fail explicitly" design rule is implementable as-is.

## What today's repo invocations actually leak

### Pi fast draft (`ts/packages/hosts/pi/src/kit/shared/fast-text-draft.ts`)

`env -u CLAUDECODE claude -p --model <m> --output-format text --system-prompt "$(cat f)"`, cwd = project dir, no isolation flags. Probe-confirmed leaks on 2.1.206:

- **Project CLAUDE.md is injected even with `--system-prompt`.** `--system-prompt` replaces the *system prompt*, but CLAUDE.md travels separately as user-level context (documented: agent-sdk "Modifying system prompts"; probe: in the marker dir the model answered `YES / BANANA-MARKER` and quoted the CLAUDE.md sentence verbatim). In this repo that means the whole `AGENTS.md` chain (imported via CLAUDE.md) rides along into every "fast draft".
- **User `~/.claude/CLAUDE.md` is injected** (probe: a baseline run in an *empty* dir still reported the distinctive content of the user's global CLAUDE.md; `--safe-mode` made it disappear).
- User/project/local `settings.json` (hooks, env, MCP servers, plugins, skills) load normally; the default tool set is available; a resumable session transcript is persisted under `~/.claude/projects/<cwd-slug>/`, and prompt history under `~/.claude/history.jsonl` (documented).
- It gets two things right: `env -u CLAUDECODE` (un-nesting) and `--system-prompt` replacing the default coding-agent system prompt (the isolated-profile probe ran at 889 input tokens — the big default prompt is demonstrably gone).

### Reviews Claude runner (`ts/packages/capabilities/reviews/src/gateways/claude-code-review-runner.ts`)

`claude -p --output-format json --bare --tools Bash,Read --model <m> --system-prompt <s> --json-schema <schema>`.

- `--bare` (verbatim help, 2.1.206; introduced v2.1.81 per CHANGELOG): *"Minimal mode: skip hooks, LSP, plugin sync, attribution, auto-memory, background prefetches, keychain reads, and CLAUDE.md auto-discovery. Sets CLAUDE_CODE_SIMPLE=1. Anthropic auth is strictly ANTHROPIC_API_KEY or apiKeyHelper via --settings (OAuth and keychain are never read). 3P providers (Bedrock/Vertex/Foundry) use their own credentials. Skills still resolve via /skill-name. Explicitly provide context via: --system-prompt[-file], --append-system-prompt[-file], --add-dir (CLAUDE.md dirs), --mcp-config, --settings, --agents, --plugin-dir."*
- Strong behavioral suppression **at the price of native login** — probe-confirmed: with only keychain OAuth available, `--bare` exits 1 with `Not logged in · Please run /login`. The runner implicitly depends on callers supplying `ANTHROPIC_API_KEY` in `options.env` (per docs, in `-p` mode `ANTHROPIC_API_KEY` is always used when present; precedence: Bedrock/Vertex/Foundry → `ANTHROPIC_AUTH_TOKEN` → `ANTHROPIC_API_KEY` → apiKeyHelper → `CLAUDE_CODE_OAUTH_TOKEN` → subscription OAuth). That is exactly the coupling the isolated profile must not inherit.
- `--tools Bash,Read` (verbatim help): *"Specify the list of available tools from the built-in set. Use \"\" to disable all tools, \"default\" to use all tools, or specify tool names (e.g. \"Bash,Edit,Read\")."* Built-ins only; MCP tools are governed separately (`--strict-mcp-config`, `--disallowedTools "mcp__*"`).
- `--json-schema`: present since ~2.1.84; **since 2.1.205 an invalid schema errors out instead of silently returning unstructured output** (CHANGELOG) — the runner's "confirm --json-schema is honored" error path matches pre-2.1.205 behavior.
- Note `--bare` does *not* claim to skip settings sources or MCP config; it skips hooks, plugin sync, and memory. `--setting-sources`/`--strict-mcp-config` remain the explicit controls for those.

### Reviews Codex runner (`ts/packages/capabilities/reviews/src/gateways/codex-review-runner.ts`)

`codex exec --model <m> --sandbox read-only --ephemeral --ignore-user-config --output-schema <f> --output-last-message <f> --color never -`.

- `--ephemeral` (verbatim help, 0.136.0): *"Run without persisting session files to disk."* Source: defined at `codex-rs/exec/src/cli.rs:30-32`; consumed at `codex-rs/core/src/session/session.rs:543` (skips thread create/resume → no rollout `.jsonl`) and `:605` (skips the state DB). `history.jsonl` is written by the TUI only — `codex exec` never writes it regardless of flags (source-confirmed). Probe-confirmed: `~/.codex/sessions/**`, `history.jsonl`, `session_index.jsonl` all byte-identical across an `--ephemeral` run; a baseline run without it added session files.
- `--ignore-user-config` (verbatim help): *"Do not load `$CODEX_HOME/config.toml`; auth still uses `CODEX_HOME`."* Source: empties only the user + profile layers of the config stack (`codex-rs/config/src/loader/mod.rs:391-419`); admin → system `/etc/codex/config.toml` → **project/cwd `.codex/config.toml` layers → `-c` runtime overrides all still apply**. Probe-confirmed both directions: with the flag, the user's configured model/effort (`gpt-5.5`/`xhigh`) and user-configured MCP servers (Notion/Linear worker-startup errors visible in baseline output) disappeared while ChatGPT-native auth kept working; without it, a planted `config.toml` (`model = "totally-bogus-model-xyz"`) was honored and failed the run (exit 1, explicit 400).
- **Gap for isolated generation:** this profile still reads project `AGENTS.md` (probe: marker obeyed and reported). Fine for Reviews — repository awareness is the point — but disqualifying for isolated generation without `-c project_doc_max_bytes=0`.

## Auth/config coupling summary

- **Claude Code couples auth to the config *directory state*, not just credentials.** Credentials sit in the macOS Keychain, yet a fresh `CLAUDE_CONFIG_DIR` reports "Not logged in": the OAuth account state in `.claude.json` is required to unlock keychain use. Directory-level isolation (the obvious "HOME-jail") is therefore unavailable on Claude Code; flag-level suppression (`--safe-mode` + `--setting-sources ""`) is the only login-preserving path. `--bare` decouples in the other direction — minimal behavior by refusing OAuth entirely — which is why it can't serve a native-login isolated profile.
- **Codex couples auth and behavior into one root (`CODEX_HOME`) but ships a first-class splitter** (`--ignore-user-config`, help text explicitly scoped: config skipped, auth kept). The splitter covers `config.toml` only; `$CODEX_HOME/AGENTS.md` and `$HOME/.agents/skills` sit outside it. The filesystem-level split (fresh `CODEX_HOME` + `auth.json` symlink) is the complete version and is probe-confirmed to preserve login.
- **Auth mode changes the behavior surface, not just credentials.** Codex model availability differs by account type (explicit 400 on ChatGPT accounts for some models). Claude Code's auth mode is silently selected by env (`ANTHROPIC_API_KEY` always wins in `-p` mode when present — documented precedence chain). The isolated profile must pin auth intent via the environment it constructs, not inherit it.

## Contract consequences

**(a) Enforceable on BOTH harnesses (contract guarantees):**

- No project instruction discovery (CLAUDE.md / project AGENTS.md) — probe-confirmed both sides.
- No user *configuration* (settings.json / config.toml incl. user MCP, hooks, model/effort defaults) — probe-confirmed both sides.
- No session/history persistence — probe-confirmed both sides.
- Native-login preservation with explicit auth-mode selection — probe-confirmed both sides.
- Single-turn text out with pinned model; structured-output option; explicit non-zero-exit failures on auth/model problems.

**(b) Harness-specific capabilities:**

- **Claude Code only:** true zero-tool requests (`--tools ""`); zero ambient skills; caller-supplied system prompt as a first-class flag; in-band structured output + usage in one JSON result event.
- **Codex only:** filesystem-level auth/config splitting (`CODEX_HOME` + `auth.json` symlink); file-based output contract (`--output-schema`, `--output-last-message`); sandbox-enforced read-only execution.

**(c) Unenforceable → explicit capability rejections (or LBYL preflight failures) in the isolated-generation profile:**

- **"No tools" on Codex** — intrinsic tool set is not removable; only containable (`--sandbox read-only`). Reject callers demanding tool-less generation on Codex.
- **"No ambient skills" on Codex** — `$HOME/.agents/skills` always injects (probe C7b); bundled skills need a config override; no wholesale off switch. Reject, or preflight-check the skill roots and fail when non-empty.
- **"No global `$CODEX_HOME/AGENTS.md`" on Codex via flags** — loaded unconditionally (source). Preflight `stat` + explicit failure, or the fresh-`CODEX_HOME` construction.
- **"Replaced system prompt" on Codex** — no exec-level instructions flag at 0.136.0; only the stdin `<system-instructions>` convention (user-level, not system-level). Reject callers requiring true system-prompt replacement on Codex.
- **Suppressing managed/policy settings on Claude Code** — `--safe-mode` keeps them by design. Document as an administrative trust boundary rather than reject.
- **Passive env isolation on both** — neither CLI ignores its environment; the profile must own env construction (allowlist) for guarantee 8 to be real.

## Recommended isolated-generation invocations

### Claude Code 2.1.206 (native OAuth preserved)

```sh
env -i PATH="$PATH" HOME="$HOME" TERM=dumb \
  <resolved-claude-binary> -p \
  --safe-mode \
  --setting-sources "" \
  --tools "" \
  --disable-slash-commands \
  --strict-mcp-config \
  --no-session-persistence \
  --model <model> \
  --output-format text \            # or: --output-format json --json-schema <schema>
  --system-prompt "<caller system prompt>" \
  "<user prompt>"                    # or via stdin
# cwd: fresh empty mkdtemp dir; delete afterward.
```

- The `env -i` allowlist subsumes unsetting `CLAUDECODE` / `CLAUDE_CODE_*` / `CLAUDE_EFFORT` / `ANTHROPIC_API_KEY` / `CLAUDE_CONFIG_DIR`; `HOME` must stay (keychain/OAuth state). Add `CLAUDE_CODE_SKIP_PROMPT_HISTORY=1` for belt-and-braces history suppression. If API-key auth is *desired*, add `ANTHROPIC_API_KEY` deliberately.
- Per-guarantee confidence: rows 1–3, 5, 6, 9, 11 probe-confirmed; 4 documented+probe-consistent; 7 probe-confirmed via empty cwd; 8 by construction; 10 probe-confirmed for residue, `uncertain` for signal semantics.

### Codex 0.136.0 (native ChatGPT login preserved)

```sh
env -i PATH="$PATH" HOME="$HOME" TERM=dumb \
  /opt/homebrew/bin/codex exec \
  --sandbox read-only \
  --ephemeral \
  --ignore-user-config \
  --ignore-rules \
  --skip-git-repo-check \
  -c project_doc_max_bytes=0 \
  -c skills.bundled.enabled=false \
  --color never \
  --model <model> \
  --output-last-message <tmpfile> \  # optionally: --output-schema <schemafile>
  - < user-prompt.txt
# cwd (or -C): fresh empty mkdtemp dir; delete tmpfiles + dir afterward.
# Preflight (fail explicitly, per the design rule):
#   - reject if $CODEX_HOME/AGENTS.md or AGENTS.override.md exists (no flag can suppress it), and
#   - reject if $HOME/.agents/skills is non-empty (no flag can suppress it)
#   — or switch to the maximal construction: CODEX_HOME=<fresh dir with auth.json symlink>
#     (probe-confirmed to preserve login), optionally with HOME=<fresh> to drop ~/.agents/skills.
```

- Do **not** set `CODEX_HOME` casually and do **not** pass `OPENAI_API_KEY` unless API-key auth is deliberately chosen.
- Per-guarantee confidence: rows 1, 2 (config half), 5–7, 9 (transport), 11 probe-confirmed; row 2 global-AGENTS.md half source-confirmed with preflight; **row 3 rejected capability**; row 4 partially enforceable (rejection/preflight for user skills); 8 by construction; 10 probe-confirmed for session/history residue.
- Caller-visible caveat: usable model IDs depend on account type; failures are explicit typed 400s (probe-confirmed).

## Open questions / residual risks

- **Codex `base_instructions`/`developer_instructions` reachability via `-c`** at 0.136.0 is unconfirmed; if reachable, Codex could gain a real system-prompt seam and (with `-c`) maybe even suppression of loaded `user_instructions`. Worth one focused probe before finalizing the Codex profile's system-prompt story.
- **`-c mcp_servers={}`** as an explicit MCP kill switch (covering hypothetical system/admin layers) is unverified.
- **Codex `--output-schema` strictness** (invalid schema / non-conforming output behavior) not established from source or probe.
- **Signal/cancellation semantics** unprobed on both CLIs. The profile should treat "kill the process group + no-persistence flags + caller-owned temp cleanup" as the mechanism and add a conformance test.
- **Codex plugins** (`~/.codex/plugins` exists on this machine): suppression by `--ignore-user-config` not separately isolated; the C7/C7b skill lists suggest plugin-scoped skills follow config layers, but label this `uncertain`.
- **Version drift.** All findings pinned to 2.1.206 / 0.136.0. `--bare` gained its hard OAuth exclusion during 2.1.x; `--json-schema` validation changed at 2.1.205; Codex config surface moves fast. The isolated profile's conformance suite should re-run the marker/auth probes per harness version rather than trusting this snapshot — which is also the honest implementation of "unsupported guarantees fail explicitly".
