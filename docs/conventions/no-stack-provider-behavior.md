# No-Stack-Provider Behavior

This convention turns [ADR 0049](../adr/0049-opt-in-provider-neutral-stacking.md)'s default into a user-facing contract. It audits the current checkout after the Branch Creation Provider cut and defines what ns must support when no Stack Provider is configured. The audit is an implementation-sequencing baseline, not a claim that submit and land have already reached the target state.

## Meaning of no provider

**No-Stack Mode** means no Stack Provider identity has been selected by a flag or typed repository setting. Passive Graphite metadata and an installed `gt` executable do not change that state and must not authorize mutation.

The current checkout has only `[workflow].branch-creation`, not the later general Stack Provider setting. Absence of that branch-creation setting already selects `plain-git`; elsewhere, “current behavior with no provider” means running without relying on Graphite configuration, metadata, or commands. This distinction prevents the existing ambient Flow behavior from being mistaken for an implicit provider selection.

Classifications:

- **Fully available** — the workflow's intended no-stacking behavior works without constructing or invoking a Graphite gateway.
- **Available with explicit limitations** — a user-facing family remains useful, but a named operation intentionally refuses or retains a Graphite-only subworkflow.
- **Unavailable** — the current command requires Graphite. A generic command in this class is migration work; an explicitly Graphite-branded command is outside the no-stacking contract.

## Supported contract

In No-Stack Mode:

1. Ordinary branch creation, checkpointing, trunk update, and plain push are supported without Graphite construction or invocation.
2. Generic submit and land select an ordinary branch target. They must never model that branch as a one-element stack or consult passive provider metadata to choose a mutating path.
3. Branch submit/land use Git facts and GitHub gateways. Stack topology, preparation, reconciliation, and publication are not available unless an explicit Stack Workflow Target selects a provider.
4. A mixed command family may retain clearly named Graphite-only operations, but portable siblings remain usable and refusals identify both the missing capability and the portable route where one exists.
5. Explicitly Graphite-branded commands are outside the no-stacking availability promise. Objective Runner is the sole parked generic exception and remains documented as unavailable pending redesign.

## Implementation sequence derived from the audit

1. Add explicit Branch Workflow Target and Stack Workflow Target selection at Flow submit and land composition roots. This closes the two generic user-facing gaps without changing provider internals.
2. Implement branch submit and branch land over Git/GitHub gateways, constructing no stack gateway in the branch arm. Preserve `flow push` as the narrower already-committed Git transport.
3. Move Herdr implementation branch preparation onto the selected Branch Creation Provider while leaving Herdr resource operations untouched.
4. Extract neutral topology, preparation, reconciliation, and publication capabilities and migrate only the explicit stack arms to Graphite adapters.
5. Reconcile contributor guidance after those paths land. Leave Graphite-branded surfaces and the parked Objective Runner out of this sequence.
